# Модуль всплывающих окон

Реализован 2026-10-02 по запросу владельца: вместо браузерных prompt/confirm
студия показывает окна в оформлении приложения. Владелец контракта — web UI.

## Граница и данные

`web/src/popups/service.ts` владеет только текущим запросом, FIFO-очередью,
статусом выполнения и ошибкой. `PopupHost.vue` владеет временным вводом,
фокусом и отображением. `App.vue` монтирует один host независимо от раздела.
Потребители Sidebar/PresetBar передают текст и callback прикладного действия;
HTTP, права, чаты, проекты и пресеты остаются у API/studio. Зависимость:
потребитель → popup service; host → service + i18n. Нет хранения в БД/localStorage.

## Публичный контракт

- `prompt(options): Promise<string | null>` — trim непустого текста;
  необязательный maxLength. Для имён чатов/проектов — серверный предел 200.
- `select(options): Promise<string | null>` — только значение из переданного
  списка. Пустая строка — допустимый ID «Без проекта», null — отмена.
- `confirm(options): Promise<boolean>` — подтверждение или false при отмене.
- `alert(options): Promise<undefined>` — сообщение с одной кнопкой.
- `onConfirm` выполняет действие до успешного закрытия. Ошибка сохраняет окно
  и введённое значение; можно повторить или отменить. Во время выполнения
  повторная отправка и отмена запрещены. Callback не должен ожидать другой
  popup из той же очереди: следующий запрос откроется после текущего.
- `dismissAll` при демонтаже host завершает ожидающие promises как отменённые.
  Уже начатый HTTP-запрос это не отменяет; его поздний ответ не закрывает
  новый popup. Обычно host живёт весь срок приложения.

## Пользовательский поток и инварианты

Создание/переименование → окно с полем → ввод/Enter → callback → закрытие
после успешной записи. Пустое имя запрещено; готовое имя выделено при открытии.
Перенос → список проектов по ID → подтверждение → moveChat. Одинаковые имена
не смешивают ID; опечатка не переносит чат в «Без проекта».
Архивация, удаление архивного чата и пресета → подтверждение с полным описанием
→ callback. Удаление визуально выделено и первоначально фокусирует отмену.
Отмена, Escape и отдельный клик по фону не вызывают callback. Во время записи
окно остаётся открыто и показывает состояние выполнения.

HTML dialog используется как оформленный элемент UI и top-layer для
блокировки фона и удержания Tab внутри окна; window.prompt/confirm/alert не
вызываются. При закрытии восстанавливаются прокрутка и фокус доступной кнопки.
Название/описание доступны screen reader, ошибки — role=alert. Есть RU/EN,
тёмная/светлая темы, ширина для мобильного экрана и прокрутка длинного текста.

## Проверка

`test/popups.test.js`: очередь, отмена без записи, пустое значение проекта,
валидация, защита от гонок, ошибка/повтор, демонтаж и поздний callback.
Автоматический сценарий `BROWSER_E2E_POPUPS_ONLY=1` в `test/browser-e2e.cjs`
проверяет собранный UI и реальные операции workspace в изолированной test-БД.
Обязательный рабочий Compose и health проверяются отдельно с общей БД.
Ручной визуальный просмотр остаётся пользователю.
