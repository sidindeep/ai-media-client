# Локализация веб-интерфейса

## Цель и границы

Модуль `web/src/i18n/` — источник локализованной статики Vue-сайта: подписей,
состояний, ошибок, accessibility-атрибутов, лендинга, подсказок для генерации и форматов дат/чисел.
Отдельные страницы входа, администрирования, `/legacy` и юридические документы используют
`public/localization-runtime.js` и `public/localization-en.js`. Промпты пользователя и текст,
вернувшийся от модели/провайдера, не переводятся.

## Контракт

- Локали имеют BCP 47-коды `ru` и `en`; `rus` и `eng` принимаются только как входные алиасы.
- `ru.ts` задаёт `TranslationKey`; `en.ts` компиляционно обязан содержать те же ключи.
- `t(key, params)` выполняет интерполяцию `{name}`; `tp(key, count)` выбирает форму числа через
  `Intl.PluralRules` и ветки `.one/.few/.many/.other`.
- Числа и даты форматируются через `formatNumber` и `formatDate`, а не через зашитый `ru-RU`.
- Выбор хранится в `localStorage` под ключом `ai-media-client.locale`; при первом запуске учитывается
  язык браузера, затем применяется русский fallback.
- При смене локали обновляются реактивный UI, `document.documentElement.lang` и статические узлы лендинга с
  `data-i18n*`.
- Новая статика не должна появляться напрямую в Vue-шаблонах; для неё добавляется namespace-ключ в оба словаря.
- Старые страницы используют русскую строку как ключ в английском словаре. Адаптер переводит
  текстовые узлы, атрибуты и сообщения, созданные скриптами, включая шаблоны с подстановками.
  Новый текст в этих страницах требует записи в `localization-en.js`; пользовательский ввод и
  результат модели не являются переводимыми ресурсами.
- Юридические страницы сохраняют исходный русский текст при выборе `ru`. Английская версия
  помечена как перевод для удобства; при расхождении смыслов действует русский оригинал.

## Проверка

- `pnpm check:web:vue` подтверждает типы ключей и паритет словарей.
- `test/localization.test.js` проверяет паритет ключей, ссылки `data-i18n*` лендинга,
  покрытие статических строк отдельных страниц и переключение локали.
- Финальная проверка выполняется только на свежей Compose-сборке с проверкой `/api/health`.
