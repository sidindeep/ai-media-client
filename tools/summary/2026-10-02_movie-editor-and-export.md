# Монтаж: сетка материалов, миниатюры и сохранение видео

## Намерение пользователя

Пользователь попросил заменить длинные формы сцен компактной матрицей материалов,
а подробности выбранного элемента разместить справа по аналогии с интерфейсом
приложения. Затем попросил миниатюры фото/видео. Последняя продуктовая задача —
исправить получение пригодного файла: скачанный предпросмотр имел артефакты и
не перематывался; пользователь также сообщил о проблемах основного экспорта MP4.

## Интерфейс материалов

- `web/src/components/MovieEditor.vue`: сетка карточек с номером, типом,
  именем, длительностью и выделением. Справа под предпросмотром — одна форма
  выбранной сцены: исходное фото/видео, описание AI, текст, длительность,
  полный клип, перестановка и удаление. На узком экране колонки последовательны.
- Выбор локальный по id, переживает перестановку. Добавление выбирает новую
  сцену; удаление — соседнюю; при отсутствии выбранного id выбирается доступная.
  AI-план может сохранять прежний выбранный id; не предполагать, что всегда
  выбирается первая сцена. Выбор не входит в серверный черновик.
- `web/src/components/MovieMaterialThumbnail.vue`: ленивые фото и видеокадр
  около 0,1 секунды через HTMLVideoElement/canvas, JPEG до 320px. Видеодекодер
  освобождается после кадра, ошибки, 15-секундного таймаута или размонтирования.
  Ошибка оставляет иконку; миниатюры не сохраняются в черновике. Типы сцен
  остались title/image/video; иконка файла — только fallback.

## Диагностика и исправление сохранения

- Приложенный пользователем `ai-media-preview.mp4` (Downloads) прочитан ffprobe/
  FFmpeg: 3 610 109 байт, около 83 секунд, H.264/AAC, 270×480. Подтверждены ошибки
  декодирования H.264 (`first_mb_in_slice overflow`, ошибки макроблоков).
  Точная первопричина повреждения на пользовательском устройстве не воспроизведена;
  нестабильная конфигурация H.264 при захвате/обрезке — гипотеза. Старый файл
  не исправлялся и не заменялся; предложено заново экспортировать монтаж.
- Проверен обязательный ai_logger HTTP-reader. Есть MOVIE_RENDER_FAILED без
  подробной категории исходного сбоя; никаких данных подключения БД не меняли.
- `web/src/remotion/record-preview.ts`: сохраняет отдельный путь захвата вкладки
  через getDisplayMedia/Region Capture, но записывает только VP8/Opus WebM,
  без прямого MP4 MediaRecorder. Видео 2,5 Мбит/с, аудио 128 Кбит/с, запрос
  ключевых кадров раз в секунду. 0–90% — запись в реальном времени.
- Новый `web/src/remotion/finalize-recording.mts`: финализация через Mediabunny.
  Сначала программный H.264/AAC MP4 с обычным индексом/fastStart=in-memory,
  постоянными чётными размерами и ключевыми кадрами раз в секунду. Если кодеки
  недоступны — индексированный WebM с копированием дорожек. Нельзя терять звук:
  discardedTracks запрещены. 90–100% — финализация, скачивание только после неё.
  Abort отменяет Conversion и освобождает Input; захват прекращается до финализации.
- `web/src/remotion/bridge.ts`: основной экспорт MP4 предпочитает программное
  кодирование, видео 5 Мбит/с, аудио 128 Кбит/с и ключевые кадры раз в секунду.
  Это изменение проверено на тестовых монтажах, но отдельная причина жалобы
  пользователя на основной экспорт по имеющимся логам не установлена.
- Обновлены ru/en пояснения, `docs/remotion-video-editor.md` и контракт
  `tools/project-memory/specs/features/remotion-video-editor.md`.

## Свежая проверка и доказательства

- После правок выполнен `docker compose up -d --build`; Vue type-check и сборка
  прошли внутри образа. Рабочие media/codex healthy, `/api/health` ok=true,
  общая БД connected. DATABASE_URL не подменялся.
- Контейнерный `BROWSER_E2E_MOVIE_GRID_ONLY=1`: выбор, редактирование, порядок,
  удаление, адаптивная раскладка, восстановление черновика, фото/видеоминиатюры,
  fallback иконки. Пройден.
- Контейнерный `BROWSER_E2E_MOVIE_ONLY=1`: MP4, запись предпросмотра, перемотка
  финализированного файла, звук, отмена, импорт, AI-сценарий, сохранение,
  навигация, reload и 16-сценный монтаж. Пройден. Тестовые селекторы обновлены
  под единственную форму подробностей; массовые правки выбирают карточки по очереди.
- Тест использует только документированную изолированную БД профиля tests.
  Опциональный MOVIE_ARTIFACT_DIR сохраняет полученные файлы для внешней проверки.
- Артефакты в `data/test-artifacts/movie/`: export-title.mp4, export-mixed.mp4,
  preview-title.webm, preview-mixed.webm, export-16-scenes.mp4. В Linux Chromium
  предпросмотр использовал WebM fallback; ветка финализации предпросмотра в MP4
  на пользовательском Windows ещё не подтверждена.
- FFmpeg полностью декодировал тестовые MP4/WebM с `-xerror` без ошибок;
  перемотка через `-ss` прошла. Последний export-16-scenes.mp4: H.264/AAC,
  720×1280, 85,525333 секунды, 2 355 862 байта; decodeExit=0,
  seekExit=0 при переходе на 70-ю секунду.

ai_logger, уточнить конкретный путь сохранения/безопасный код ошибки и проверить
новый файл. Не выдавать тестовый монтаж за восстановленный пользовательский ролик.
