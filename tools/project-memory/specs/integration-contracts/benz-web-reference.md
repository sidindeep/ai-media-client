# Benz AI как ориентир для веб-версии

Изучено 2026-09-17 по явному запросу пользователя. Источник — соседний проект
`../benz_ai` относительно корня текущего проекта. Это источник архитектурных
примеров, не runtime-зависимость. Внешний проект не изменялся; секреты, данные
пользователей и журналы не читались. Исследование статическое, запуск и тесты
Benz AI не выполнялись.

## Намерение и статус

Обновление 2026-09-18: пользователь разрешил прочитать схему БД и авторизацию
источника для внедрения собственных аккаунтов. Повторно прочитаны
services/analytics.js, services/payment-store.js, config.js и документация.
Подтверждены PostgreSQL через pg.Pool для аналитики и JSON для тестовых оплат;
Google/VK OAuth в источнике нет. В AI Media адаптирован pg.Pool подход, своя схема
аккаунтов разработана отдельно. Источник не изменялся, секреты не читались.
Новый контракт: ../features/accounts-credits.md. Текст ниже — прежний этап.

Пользователь хочет веб-версию AI Media Client и попросил изучить структуру,
шаблоны и модули Benz AI. Перенос конкретных модулей, подключение платежей,
Telegram или аналитики пока не согласованы. Режим доступа (локальный, личный
через интернет или многопользовательский) остаётся открытым.

## Проверенная структура источника

- `server.js`: встроенный Node HTTP-сервер, маршруты API, статика из `public/`,
  сборка сервисов, health endpoint, ограничения запросов и заголовки защиты.
  Здесь также остаётся существенная оркестрация поиска; это не тонкий router.
- `config.js`: чтение окружения, настройки источников, таймаутов и лимитов.
- `domain/`: нормализация и объединение станций, ограниченный кэш.
- `providers/`: адаптеры внешних систем, включая источники станций, LLM и ЮKassa.
- `services/`: прикладные сценарии, геокодирование, Telegram, аналитика и
  тестовые подписки; платёжный сервис получает клиент и хранилище через конструктор.
- `public/`: статический HTML/CSS и браузерные ES-модули. `app.js` связывает
  интерфейс; отдельно выделены API-клиент, карта, фильтры, представления и колонки.
- `templates/TECHNOLOGY_STACK.template.md`: шаблон документации, не UI-kit.
  Карточка станции задана HTML-элементом `template` в `public/index.html`.
- `Dockerfile`: упаковка Node-сервера, непривилегированный пользователь и
  healthcheck. Chromium нужен специфическому адаптеру Sber.
- Тесты используют встроенный Node test runner. Зависимость `pg` обслуживает
  аналитику; наличие PostgreSQL не означает единую БД всех данных продукта.

## Предлагаемое применение в AI Media Client

Это предложения, а не уже выполненная миграция:

1. Браузерный транспорт заменяет вызовы Electron IPC из `src/preload.js`;
   общий UI продолжает использовать декларативный каталог и формы.
2. Серверные сервисы управляют очередью, историей, черновиками, исходниками и
   результатами; существующие `TaskQueue`, `History`, `Assets`, адаптеры и
   расчёты стоимости сохраняются как исходная бизнес-логика.
3. Ключ Kie и обращения к провайдеру остаются на серверной стороне.
   Electron safeStorage требует отдельной замены для серверного окружения.
4. Native-операции (выбор папки, reveal, уведомления, отдельная сессия Kie)
   требуют явных браузерных аналогов либо обозначенных ограничений.
5. Сохранить инварианты: неоднозначный POST не повторяется; пауза останавливает
   отправки, но не опрос; неполный запрос допустим как черновик; неизвестная
   стоимость не равна нулю.
6. Общая логика должна оставаться общей для desktop и web. Платёжные,
   картографические и Telegram-модули Benz AI не нужны для самого переноса.

Для нескольких пользователей необходим отдельный контракт авторизации и
изоляции ключей, очередей, истории и файлов. Рассмотренный веб-каркас сам по
себе этого не предоставляет. Завершение браузерной вкладки также не может
использовать Electron-протокол `drafts:close`.
