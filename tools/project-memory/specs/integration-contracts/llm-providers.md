# Источник шаблонов LLM Providers

## Одноконтейнерный хостинг Bothost

После обнаружения отсутствующего Codex на Bothost корневой Dockerfile
AI Media Client дополнен CLI 0.155.0 и MEDIA_CODEX_EMBEDDED=true.
server.js запускает внутренний worker на loopback 3210 и останавливает его
при завершении. CODEX_HOME=/app/data/codex-auth сохраняется средствами хостинга.
Процесс CLI не наследует DATABASE_URL/OAuth/Kie secrets из среды веба.
Compose явно отключает embedded, сохраняя прежние два контейнера и auth volume.
Изменение образа требует нового деплоя и device login в терминале Bothost;
локальный вход на удалённый хост не переносится. Удалённый деплой этим
изменением не выполнен. Инструкция: docs/codex.md.
Проверены 16 целевых тестов и свежий одноконтейнерный образ: CLI 0.155.0,
PORT=8080, health веба и приватного worker, запись в каталог авторизации,
остановка worker вместе с вебом. Проверка образа без входа и генерации.

## Codex в Docker — проверка 2026-09-18

### Каталог в боковом меню веба

`scripts/sync-codex-models.cjs` получает все страницы `model/list` с
`includeHidden:false` через авторизованный Docker-провайдер. В
`config/codex-models.json` хранится снимок: дата, версия CLI, ID и названия
моделей, уровни рассуждения и входные модальности. Секреты и сведения аккаунта
не экспортируются. На 2026-09-18 получены gpt-6-astra, gpt-5.6-sol,
gpt-5.6-terra, gpt-5.6-luna, gpt-5.5. Это каталог runtime, не проверка
генерации каждой моделью и не гарантия доступа другим аккаунтам.

Веб явно переключает провайдера Kie.ai/Codex CLI. Codex генерирует текст или PNG;
модель, поддерживаемый уровень рассуждения и standard/fast передаются worker.
Выбор и черновик сохраняются в localStorage с привязкой к аккаунту.
По указанию пользователя от 2026-09-18 серверный Codex доступен всем
авторизованным пользователям за внутренние кредиты. Тариф задаётся отдельно
для `codex:<model>:<effort>:<speed>` в существующем pricing config; без цены
запуск запрещён. До запуска резерв, после успеха списание, при подтверждённом
отказе возврат; неизвестный результат сохраняет резерв без автоповтора.
Пользователь утвердил временную цену, равную Nano Banana 2 Lite: 4 внутренних
кредита за запрос для всех 54 режимов Codex (включая Fast/ultra).
Задания и результат хранятся в PostgreSQL `media_records`, namespace `codex`;
ссылки резерва имеют вид `codex:<accountId>:<requestId>`. Админская сверка
поддерживает эти ссылки. Web-процесс восстанавливает проверку заданий при старте.
Пользователь получает доступ только к своим заданиям и своему кошельку.

`Dockerfile.codex` расширяет `llm-providers:local` приватным HTTP worker;
порт 3210 не публикуется. Веб не монтирует Docker socket или Codex credentials.
Auth volume монтируется только в non-root worker с read-only rootfs.
CLI запускается без пользовательских конфигов/правил, в read-only sandbox,
с отключёнными shell/browser/apps и другими инструментальными features.
Для режима изображения включены image_generation/code_mode/code_mode_host.
PNG берётся из generated_images по thread.started, проверяется и сохраняется
в MEDIA_DATA_DIR/codex-images; путь из текста модели не используется.
Файл выдаётся только владельцу через /api/codex/jobs/:id/image.
Текст без PNG в режиме image возвращает резерв, а не списывает кредиты.
Один активный запрос, таймаут текста 180 секунд, изображения 300 секунд;
сырой stderr пользователю не отдаётся.
Исправление изображений проверено на реальном worker: gpt-6-astra/medium/standard
с kind=image вернул PNG 1370×1148 (2 031 015 байт), визуально проверен кот у окна.
Локальное доказательство вне Git: `artifacts/codex-image-smoke.png`.
5 тестов Codex проверяют в том числе принадлежность файла текущему thread,
возврат резерва при отсутствии PNG и границы инструментов. Скрытый UI smoke
проверяет показ/скачивание PNG и запрет доступа другого аккаунта.
Операционный контракт и актуальная граница тарифов: `docs/codex.md`.

Пользователь подтвердил каталог `../llm_providers` (локально
`D:\AI\llm_providers`). Это рабочий источник адаптеров провайдеров.
По package.json требуется Node >=20. В src/providers/codex-cli/index.mjs
адаптер запускает `codex exec`, создаёт временный workspace и поддерживает
JSON Schema; в src/providers/codex-app-server/index.mjs адаптер запускает
`codex app-server` и общается через stdin/stdout JSON-RPC. На Linux резолвер
использует команду `codex`; обязательной зависимости от Windows в этом пути нет.

Вывод по исходникам: адаптер и Linux Codex CLI можно упаковать вместе в
контейнер. Существующий bin/llm-provider.mjs принимает JSON через stdin;
это процессный мост, не HTTP-сервис. Для отдельного сетевого сервиса нужна
обёртка API с фиксированной серверной конфигурацией, таймаутами и ограничением
параллелизма. Одной замены URL недостаточно: оба адаптера запускают subprocess.
Авторизацию следует хранить отдельно от образа в постоянном приватном томе.
Официальная документация описывает headless/device login и Docker:
https://learn.chatgpt.com/docs/auth.

По последующему запросу «делай» в исходной библиотеке добавлены Dockerfile,
Compose и docs/docker.md. Образ `llm-providers:local` собран: Node 22,
Codex CLI 0.155.0, системные CA-сертификаты, non-root, read-only rootfs,
tmpfs и отдельный auth volume. Проверены требуемые флаги exec, JSON-мост,
Unicode, права записи и отказ на неверном JSON; 20 тестов библиотеки прошли.
Вход по device code завершён пользователем; новый контейнер подтвердил
`Logged in using ChatGPT`, что проверяет сохранение авторизации в томе.
Реальные запросы через codex-cli (с JSON Schema) и codex app-server на
`gpt-5.6-sol` вернули `{"status":"ok"}` и завершились с кодом 0.
Исходный контейнер библиотеки — одноразовый stdin worker; отдельная HTTP-обёртка
для веба теперь принадлежит AI Media Client (описана выше).
Текстовый запрет инструментов сам по себе не является изоляцией; CLI-адаптер
задаёт read-only sandbox, а app-server передаёт sandbox/permissions как null.
Не считать эти два адаптера равноценными по ограничениям доступа.

## Проверенный контракт

По README, package.json и src/: это приватный ESM-пакет `llm-providers`
версии 0.1.0, Node >=20, без runtime-зависимостей. Реализации находятся в
`src/providers/`, а `templates/` содержит шаблон документации стека.

- Адаптеры: DeepSeek, OpenAI-compatible, LM Studio, Codex app-server,
  Codex CLI, mock. Названия подтверждены экспортами и реестром; реальная
  работоспособность внешних сервисов в этом исследовании не проверялась.
- `loadProviderConfig` нормализует конфигурацию;
  `createProvider` / `generateWithActiveProvider` выбирают адаптер.
- Вход: prompt или messages, model, temperature, maxTokens, output.
- Выход: provider, model, output, parsed, raw.
- Контракт output поддерживает выделение JSON-блока, JSON parsing,
  jsonSchema для поддерживающего адаптера и валидатор вызывающей стороны.
  Сам jsonSchema не означает локальную валидацию результата: её нужно
  задавать через validate (проверено по outputContracts.mjs).
- HTTP-адаптеры используют chat completions; DeepSeek и LM Studio строятся
  на общей реализации. LM Studio нормализует суффикс /v1.
- `bin/llm-provider.mjs` / `providerBridge.mjs` предоставляют JSON stdin-мост.

## Применение в веб-версии

Использовать как одобренный источник серверных LLM-адаптеров, когда определён
пользовательский сценарий LLM. Сценарии написания/перевода промптов пока
не запрошены явно; не считать их согласованными функциями.
Генерация изображений/видео через Kie остаётся отдельным контрактом:
chat-completions адаптеры не заменяют очередь медиа-задач и их опрос.

Конфигурация, секреты и выбор разрешённого провайдера принадлежат серверу;
нельзя напрямую открывать клиенту произвольный config-envelope, URL или
команду локального процесса. Перед переносом HTTP-адаптера добавить границу
таймаута/отмены и безопасные ошибки: в текущем исходнике fetch не получает
signal, а ошибка включает фрагмент тела ответа провайдера. Не отдавать raw
наружу без нужды. Codex-адаптеры зависят от отдельного локального runtime.

Форма подключения (адаптация выбранных файлов либо пакет) пока не выбрана.
Не закреплять машинный абсолютный путь в runtime и не менять текущий
CommonJS-проект целиком ради ESM-пакета. Исходный проект изменять только по
отдельному запросу.
