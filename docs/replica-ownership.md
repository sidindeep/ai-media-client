# Владение задачами при нескольких веб-репликах

Процесс с `MEDIA_REPLICA_ROLE=executor` выполняет очереди Kie, Codex и
RouterAI, сохранение контента, Telegram polling и доставку платёжного outbox.
Процессы с `MEDIA_REPLICA_ROLE=web` обслуживают чтение, историю и SSE; все
HTTP-операции записи, включая загрузки и платные отправки, потоково направляют
на executor по `MEDIA_EXECUTOR_URL`. `single` сохраняет поведение одного процесса.

Глобальная блокировка executor в PostgreSQL удалена по решению владельца
от 2026-09-30: несколько ПК с Docker могут подключаться к общей БД без
`EXECUTOR_BUSY`. Файловый `service.lock` защищает только один каталог данных.
Отдельное соединение и таймер проверки владения больше не создаются.
После старта безопасные `queued` задачи
восстанавливаются, а прерванные `submitting` без ID провайдера остаются `unknown`
до сверки. Их нельзя автоматически отправлять повторно.
Транзакционная блокировка конфигурации преобразования параметров использует
отдельный ключ `18274694`, поэтому веб-реплики и повторные запуски могут
подготовить конфигурацию, пока executor удерживает владение.

Основной `compose.yaml` запускает `media` как executor. Дополнительный
`media-web` включается профилем `replicas` и публикуется локально на 3002;
дальнейшая балансировка общего публичного origin настраивается снаружи Compose.
Его пул задаётся `MEDIA_WEB_DB_POOL_MAX` (по умолчанию 2).

Все реплики используют одну PostgreSQL и один каталог `MEDIA_DATA_DIR`, доступный
по одинаковому относительному пути. Это обязательно для локальных исходников,
staging контента и результатов; при S3 локальный staging всё равно должен быть
общим до завершения загрузки. Веб-реплики не запускают свои очереди, content
worker, Telegram polling, embedded Codex/Kie browser и восстановление
Codex/RouterAI. Обновления аккаунтов доставляются через PostgreSQL LISTEN/NOTIFY,
поэтому SSE на другой реплике получает изменения. При недоступном executor
чтение остаётся доступным, а запросы записи получают HTTP 503.

`MEDIA_EXECUTOR_URL` у web указывает на executor только по доверенной внутренней
сети. `MEDIA_EXECUTOR_PUBLIC_ORIGIN` задаёт Host/Origin, который разрешён
executor. Авторизация и проверка Origin применяются на обеих сторонах.
В `compose.yaml` локальный web-порт 3002 использует `MEDIA_WEB_PUBLIC_ORIGIN`
(по умолчанию `http://127.0.0.1:3002`); при общем внешнем origin задайте его
равным `MEDIA_PUBLIC_ORIGIN`. Сумма `MEDIA_DB_POOL_MAX` всех реплик,
LISTEN-соединения должны помещаться в лимит
PostgreSQL с запасом.

Режим web масштабирует чтения и SSE и направляет записи на настроенный executor.
Одновременный запуск независимых executor теперь разрешён, но не реализует
распределённое владение задачами: восстановление очередей и фоновые операции
могут пересекаться. Для гарантии отсутствия повторной обработки между ПК нужны
lease/fencing для каждой задачи, общий лимитер и межузловой staging.
