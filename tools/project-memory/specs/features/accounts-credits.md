# Аккаунты и нативные кредиты

Публичный маршрут `/` не требует сессии и показывает рекламный лендинг. Рабочая
студия находится на `/app`: без сессии она перенаправляет на `/login`, а успешный
OAuth callback возвращает пользователя на `/app`. Статические файлы лендинга не
инициализируют пользовательское хранилище и остаются доступны при временной
недоступности базы; защищённые API и пользовательские файлы доступ не ослабляют.

## Актуализация Codex — 2026-09-18

По указанию владельца серверный Codex доступен всем пользователям через их
внутренние кредитные счета. В `config/native-prices.json` опубликованы
все 54 режима Codex по 4 кредита за запрос. Переключатель веба явно
разделяет Kie (медиа) и Codex (изображения/текст), для Codex доступны модель, effort и
standard/fast. Резерв и финализация используют существующий кошелёк;
неизвестное завершение удерживает резерв до сверки. Контракт:
[llm-providers](../integration-contracts/llm-providers.md), инструкция:
[Codex](../../../../docs/codex.md).

Актуализация Kie — 2026-09-20: production-модели Kie рассчитываются по
публичному тарифному каталогу Kie. Account-scoped сервис сопоставляет строку по
точному model id из query-параметра `model` поля `anchor`, затем выбирает вариант
по параметрам запроса. Тариф кэшируется на 24 часа. Явный Kie override в
`config/native-prices.json` допустим только для контролируемого тестового или
специального окружения. Неоднозначное сопоставление,
неподдерживаемая единица или отсутствующий тариф блокируют резерв, а не подставляют
нулевую либо угаданную цену. Внутренний кредит этого маршрута равен одному
тарифному кредиту Kie; `per second` умножается на `duration`, `per image` — на
количество результатов внутри одной задачи. Диапазон Kie `1/2K` считается
точным тарифным уровнем для запросов `1K` и `2K`, но не для `4K`.

Проверены 32 web-теста, скрытый UI smoke с платным запросом обычного
пользователя и администратора, изоляция результатов и неизменность черновика
Kie. Реальный worker ответил на gpt-5.6-sol/low в standard и fast;
каждая модель/уровень отдельно не проверялись. Ниже сохранена история внедрения.

Запрос 2026-09-18: Google/VK OAuth с расширяемыми провайдерами идентичности,
изолированные аккаунты, своя история и счёт, роли user/admin. Разработчик видит
внутренние провайдерские данные; пользователи видят цену сервиса. Математика
кредитов — отдельный модуль. Продажа кредитов и маршрутизация по провайдерам
запланированы; алгоритм балансировки и коммерческие тарифы не выбраны.

## Реализация и источники истины

- `src/auth/`: реестр адаптеров Google/VK, серверный обмен code, userinfo,
  одноразовые state с привязкой к браузеру, PKCE, хешированные серверные сессии.
  Идентичность — `(provider,subject)`, email не склеивает аккаунты.
- `src/database/schema.sql`: версия схемы 1, PostgreSQL аккаунты, identities,
  sessions, OAuth flows, tenant records, wallets, reservations, ledger,
  reconciliations. `database.js` применяет схему с advisory lock.
- `AccountRecords` ограничен account_id + namespace; транзакция с блокировкой
  кошелька объединяет запись истории, резерв/финализацию и проводку.
- `src/services/accounts.js`: отдельный MediaService на аккаунт, DTO allowlist
  для user, admin workspace selector, восстановление отправленных задач.
- `src/billing/pricing.js`: целые минимальные единицы, 1000 на кредит,
  versioned base + per-second product price. `config/native-prices.json` хранит
  опубликованные цены Codex; Kie использует динамический публичный каталог.
  Внешний `costs.js` используется только для внутренних расходов.
- `src/billing/wallet.js`: баланс/резерв, идемпотентное начисление админом,
  резерв/списание/освобождение. Различаются grant и будущий purchase.
- `provider-router.js`: точка будущего выбора; сейчас один Kie, без fallback.
- Веб: `/login`, общие формы с отдельным `native-costs.js` для user,
  `/admin.html` для счетов и выбора пользователя. Проверка прав всегда серверная.
  Пополнение в админке выбирает свой кошелёк по умолчанию, позволяет начислить
  кредиты другому аккаунту с причиной и показывает доступный баланс/резерв.

## Инварианты

1. Сервер берёт владельца из сессии. Нельзя выбрать accountId из клиентского
   тела; admin selection отдельно проверяется. Включая SSE и файловые маршруты.
2. Новый аккаунт user и нулевой баланс; admin по явному provider subject,
   одноразовому серверному приглашению для подтверждённого Google email либо
   назначению действующим администратором. Не присваивать роль первому вошедшему.
3. Постановка с резервом атомарна; уникальный requestId внутри аккаунта.
4. success списывает фиксированную цену; fail/cancelled/blocked освобождают.
   unknown/unconfirmed сохраняют резерв; удаление из очереди не снимает его.
   Ручная сверка сохраняет actor и evidence и не выполняет новый POST провайдеру.
5. Повтор callback/state, запроса генерации, начисления или финализации не
   создаёт второй аккаунт/задачу/списание. Изменённый payload с прежним ID — ошибка.
6. UI пользователя и API не раскрывают баланс/себестоимость провайдера.
7. .env и медиаданные вне Git. Файлы находятся в tenant-каталогах; хранилище
   accounts требует резервной копии БД вместе с файловым каталогом.
8. По уточнению пользователя администратор подчиняется той же логике нативных
   тарифов, баланса, резерва и списания, что и user. Бесплатного обхода нет.
   В legacy-пространстве нельзя создавать новые генерации без кошелька.

## Этапы и критерии

Обновление управления аккаунтами: схема v2 хранит подтверждённый Google email,
одноразовые назначения владельца и аудит ролей. Изменение роли завершает сессии;
последний admin защищён общей транзакционной блокировкой. Явное понижение не
отменяется env allowlist или повторным использованием приглашения. Меню аккаунта
содержит баланс, пополнение, профиль, настройки, историю и выход; панель admin —
поиск пользователей, роли, начисления, журнал кошелька/ролей и ручную сверку.
Для указанного пользователем владельца создано приглашение в удалённой БД;
назначение ожидает подтверждённого Google-входа через обновлённый сервер.
Проверены SQL/HTTP права, одноразовое назначение, отзыв сессий, UTF-8 и DOM-сценарии
профиля/настроек/ролей/начислений. Реальный вход владельца ещё не проверен.
Итог: 25 web-тестов и скрытый DOM smoke прошли; Docker пересобран и healthy.
Гонка очистки web/Telegram-тестов устранена: сначала закрывается сервис/очередь,
затем удаляется его временный каталог. На хостинг новая версия не развёрнута.

Полная проверка сборки 2026-09-18: 24 web и 50 desktop unit/integration тестов
прошли; Windows pack в единственный desktop/dist/queue-header обновлён,
packaged Electron smoke проверил 149 форм. Docker Desktop запущен, образ
ai-media-web-tg:local собран; проверены включение схемы/цен и отсутствие
.env/desktop/PGlite. Контейнер приложения параллельно локальному серверу не запускался.
Новый test/web-ui-smoke.cjs проверяет настоящий DOM веба со скрытым окном,
изолированным PGlite и подставным провайдером: native price/spending, отсутствие
провайдерских финансов, logout, admin list и начисление 1.25 кредита.
Работающий localhost:3000: health, login, запрет анонимного API, Google redirect,
PKCE и отменённый callback проверены. На реальной PostgreSQL повторно проверены
резерв, идемпотентное списание и rollback тестового аккаунта. Полный Google/VK
вход и реальные генерации не выполнялись. Google credentials уже настроены
локально; VK, admin identities и коммерческие тарифы требуют настройки.

Обновление подключения 2026-09-18: в указанной пользователем отдельной удалённой
PostgreSQL развёрнута схема v1 (10 таблиц); до применения таблиц не было.
Подключение сохранено только в игнорируемом `.env`, без реквизитов в памяти/Git.
Сервер не поддерживает TLS; после явного разрешения пользователя используется
DATABASE_SSL=0. На реальной БД проверены повторное применение схемы, UTF-8,
резервирование и идемпотентное списание; тестовые данные полностью откачены
ROLLBACK. Google/VK OAuth-приложения остаются ненастроенными.

- Реализованы: схема и модули; OAuth adapters/session lifecycle; tenant isolation;
  account/role API; отдельный кредитный расчёт; admin inspection/grants/reconcile;
  тесты, конфиг и инструкция включения.
- Проверки: `test/accounts.test.js`, `test/oauth-providers.test.js`, регрессии
  web/bot. SQL выполняется PGlite, HTTP провайдеры подставные. Живые OAuth и
  сетевой PostgreSQL требуют конфигурации пользователя и не подтверждены.
- Следующее по отдельному решению: коммерческие тарифы; подключение оплаты;
  привязка Telegram; связывание OAuth identities; несколько генерационных
  провайдеров, лимиты/балансировка; серверная миграция legacy при необходимости.

Существующая JSON-история не мигрируется и остаётся admin-only legacy workspace.
Desktop не меняется. В auth-режиме старый Telegram выключен, чтобы не обходить
кошелёк; локальный owner-only режим сохраняется явным MEDIA_AUTH_ENABLED=false.

Архитектурный источник: Benz AI `services/analytics.js`, `services/payment-store.js`,
`config.js`, README/package.json, прочитаны 2026-09-18 по разрешению пользователя.
Заимствован PostgreSQL pg.Pool/DI подход. OAuth или единой аккаунтной БД в источнике
нет; его runtime-данные и секреты не читались. Инструкция: docs/accounts-and-credits.md.

Диагностика localhost: подтверждены EAI_AGAIN и тайм-ауты подключения к удалённой БД.
Docker DNS вынесен в MEDIA_DNS_PRIMARY/SECONDARY; statement_timeout задаётся через
SET после подключения, не startup-параметром. Инициализация схемы повторяется
только при временных сетевых ошибках. Health проверяет БД; при потере связи HTML
показывает страницу повтора с HTTP 503. После перезапуска проверены HTTP 200
главной страницы с авторизованной сессией, API аккаунта и скрипта меню.
Соединения пула используют keepAlive и закрываются после 30 секунд idle; временные
ошибки получения соединения повторяются до трёх попыток (promise/callback pg),
но запросы и денежные операции не повторяются. Проверены оба интерфейса пула,
отказ повторять ошибку авторизации и HTTP 503 без раскрытия внутренних данных.

По повторному запросу владельца роль admin назначена оператором единственному
Google-аккаунту с точным именем со скриншота Dima Fil; записан аудит. Email этим
действием не подтверждался. Нативный баланс загружается независимо от ключа
провайдера; admin getBalance также возвращает кошелёк выбранного аккаунта.

Черновики веба восстанавливаются по уникальному стабильному model.id при смене
роли: публичный provider media и внутренний kie не означают разные модели.
Текущий provider берётся из каталога; неизвестная/неоднозначная модель по-прежнему
отклоняется. DOM smoke проверяет переходы kie → media и media → kie с сохранением
промпта. Для desktop строгая проверка provider сохранена.

Состояние PostgreSQL доступно через `/api/health.database` и отображается в
карточке сервиса; UI обновляет его каждые 10 секунд. Пул PostgreSQL ограничен
пятью соединениями и сохраняет их между health-проверками, поскольку внешний
прокси периодически блокирует создание новых сессий (`Connection terminated` /
timeout).
