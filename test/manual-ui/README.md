# Ручное UI-тестирование для агентов

Это точка входа для агента, которому поручили проверить интерфейс вручную.
Действуй через видимый UI доступными документированными browser-инструментами.
Назначение этой папки — навигация и начало работы; полные промпты, настройки
и логика каждого сценария имеют отдельные канонические документы.

## Быстрый запуск

Передай агенту:

```text
Прочитай AGENTS.md и test/manual-ui/README.md.
Выполни сценарий «Цены генераций и доступность моделей» из таблицы сценариев.
Используй его полный промпт и настройки, работай через UI без запуска генераций.
Сохрани отчёт и checkpoint, восстанови исходное состояние, укажи покрытие
и непроверенные области. Соблюдай обязательный порядок проверки среды проекта.
```

Эта инструкция запускает работу агента, а не готовый скрипт. Сохранение документа
или чтение старого отчёта не означает нового выполненного теста.

## Сценарии ручной проверки

| Сценарий | Покрытие | Промпт и статус |
| --- | --- | --- |
| Цены генераций и доступность моделей | Провайдеры, режимы, ID/alias, обязательные поля, конечная цена, «Автомат», доступные роли | [Готовый сценарий](../../docs/model-ui-audit-prompt.md). Ручной обход выполнялся; ограничения указаны в baseline. Автоматического исполнителя нет. |

Другие сценарии добавляй по отдельной задаче. Для каждого укажи область,
промпт/настройки, контракт логики, допустимые действия и место результатов.
Сценарий с реальным запуском генерации требует явного разрешения владельца
и заданного бюджета; инструкция текущего аудита такого разрешения не даёт.

## Как агенту работать

1. Уточни область по поручению: полный каталог или затронутые ID. Не меняй
   область на исправления продукта, импорт тарифов или запуск платных задач.
2. Проверь текущую среду по runbook. Открой разрешённый адрес приложения,
   используй авторизацию владельца. При необходимости вход выполняет человек;
   не извлекай cookies и не меняй роль/подключение БД ради проверки.
3. До изменения формы подготовь отдельный тестовый чат и долговременный
   приватный backup исходного состояния. Если это невозможно, не занимай
   личный чат: продолжай только независимые чтения и укажи blocker.
4. Следуй полному промпту сценария. Выбирай модель по проверенному ID,
   подтверждай фактический режим/провайдера и дожидайся актуального quote.
   Не нажимай отправку/генерацию/повтор и горячие клавиши запуска.
5. Сохраняй результаты и checkpoint небольшими порциями. Не считай отсутствие
   предварительной оценки доказательством недоступности модели. Отдельно
   фиксируй расходный тариф, недостающие входы, неподдерживаемый вариант и сбой.
6. Восстанови состояние из backup, дождись автосохранения и повторно проверь
   сохранённый черновик. Закрой только созданные агентом временные вкладки.
7. Отчитайся о найденных проблемах, покрытии, пропусках, состоянии восстановления
   и проверке среды. Наблюдение сетевых запросов и отсутствие действий запуска
   указывай раздельно. Не объявляй непроверенное поведение исправным.

Если меняешь файлы проекта, перед итоговой проверкой обязательно выполни
Docker-пересборку и health по runbook. Недоступный Docker или неработающий health
оставляют эту проверку незавершённой; host-проверки её не заменяют.

## Где сохранять результаты

Для текущего сценария используй пути из его настроек:

- `outputs/model-ui-audit/<runId>/` — настройки, inventory, cases, checkpoint,
  сводка и проверенные снимки без личной истории.
- `data/service/ui-audit-private/<runId>/` — приватный backup для восстановления;
  не отправлять в общий отчёт, память, журналы или Git.
- `tools/project-memory/specs/features/model-ui-audit.md` — только компактные
  проверенные выводы/ограничения и ссылки на свидетельства, если нужно обновить логику.

Используй новый ID запуска, не перезаписывай предыдущие результаты.
Исторические отчёты от 2026-10-01 перечислены в контракте логики; в другом checkout
они могут отсутствовать. Новому запуску это не мешает, старые числа не являются
нормой актуального каталога.
