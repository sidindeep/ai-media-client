# История расходов

Веб-раздел `/app/spending` показывает операции внутреннего кредитного счёта за последние 7, 30 или 90 суток. Он не заменяет историю результатов `/app/history`. Ссылка из операции открывает результат, если соответствующая запись ещё существует.

## Источник истины

- `media_ledger` — единственный источник сумм. `capture` означает фактическое списание; `release` означает освобождение удержанного резерва. `reserve` не входит ни в расходы, ни в возвраты.
- Третья карточка называется «Возвращено из резерва». Возврат ранее списанных кредитов в текущем журнале не реализован и не смешивается с `release`.
- Период — скользящие 7/30/90 × 24 часа по `media_ledger.created_at`. Времена фильтруются на сервере в UTC, показываются браузером в локальном часовом поясе.
- Категория и модель новых конечных операций сохраняются в `media_ledger.details` при финализации задачи в той же транзакции. Возможные категории: image, video, text, audio, other. Неизвестные форматы относятся к other.
- Для старых проводок без снимка данные берутся из соответствующей записи `media_records`, если она сохранилась. Если запись удалена, проводка и сумма остаются, а категория становится other и ссылка на результат отсутствует.

## Контракт выдачи

`getSpending({ days, category, asOf?, cursor? })` вызывается через существующий авторизованный RPC в области текущего аккаунта. Пользователь не передаёт accountId. Администратор может использовать уже существующий механизм выбора аккаунта. Допустимые периоды: 7, 30, 90; категории: all, image, video, text, audio, other.

Ответ содержит `summary.spentUnits`, `summary.releasedUnits`, `summary.topCategory`, `items`, `nextCursor`, `asOf`. Все суммы хранятся в минимальных единицах: 1000 единиц на кредит. Итоги рассчитываются по всему отфильтрованному периоду на сервере и не ограничены размером страницы. Список выдаётся по 30 операций `capture`/`release` в порядке `(created_at,id)` по убыванию; курсор и `asOf` фиксируют границу последующих страниц. Фильтр категории применяется к карточкам и списку одинаково. `topCategory` определяется только по списаниям.

## Интерфейс

Фильтры периода и типа контента, три итоговые карточки, список списаний и освобождений резерва, загрузка следующей страницы, пустое состояние и ошибка с повтором. Интерфейс обновляется при событии изменения данных с ограничением частоты запросов; фоновое обновление сохраняет показанные карточки, строки и загруженные страницы до ответа сервера. Только явная смена фильтра сбрасывает текущую выдачу. Числа показываются с точностью до трёх знаков без округления вверх, в отличие от предварительной цены генерации.

Проверки: `test/spending-history.test.js` покрывает границы периода, разделение списания и резерва, изоляцию аккаунтов, фильтр и пагинацию; `test/accounts.test.js` проверяет авторизованный RPC. После изменения файлов обязательна пересборка Compose, `docker compose ps` и `/api/health` перед итоговой проверкой поведения.
