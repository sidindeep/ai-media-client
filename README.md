# AI Media Web + Telegram

Веб-интерфейс и Telegram-бот находятся в корне репозитория. Исходников Windows-клиента в текущем checkout нет; историческая версия хранится в `desktop.7z`.

Полная наглядная карта архитектуры, технологий и инфраструктуры:
[технологический стек AI Media Client](tools/project-memory/specs/technology-stack.md).

Веб поддерживает аккаунты Google/VK, отдельную историю и баланс нативных кредитов,
роли пользователя и администратора. [Настройка БД, OAuth и цен](docs/accounts-and-credits.md).
Покупка кредитов через test-заглушку доступна для проверки интерфейса. Денежный модуль ЮKassa частично реализован; live-оплаты и возвраты не подтверждены.

## Запуск

Нужны Node.js 22.12+, pnpm 11.19.0 и PostgreSQL. Сначала настройте `.env` по
`.env.example`: DATABASE_URL, публичный HTTPS origin и OAuth-приложения.
Для прежнего локального режима владельца доступен явный MEDIA_AUTH_ENABLED=false
только на loopback и без публичного origin. Выполняйте команды из этой папки:

```powershell
pnpm install --ignore-workspace --frozen-lockfile
pnpm start
```

Открыть http://127.0.0.1:3000 — это публичная главная AI Media Client. Главная и новая Vue-студия на `/app` работают в одной SPA-оболочке: после первоначальной загрузки переходы между ними не перезагружают документ и сохраняют данные студии в памяти. Внутренний обзор доступен на `/app/home`, а прежняя DOM-студия сохранена на `/legacy`. Остановить — Ctrl+C. Разработка: `pnpm dev`.

Для web-фронтенда: `pnpm build:web` собирает Vue/Vite-приложение в `public/vue`, `pnpm check:web:vue` проверяет TypeScript. Docker-образ проверяет типы и собирает Vue из текущих исходников. Backend и API остаются общими для обоих интерфейсов.
Проверки: `pnpm check` и `pnpm test`.

### Ручное тестирование цен через UI

Точка входа для тестирующих агентов: [test/manual-ui/README.md](test/manual-ui/README.md).
Общая навигация по тестам: [test/README.md](test/README.md).

Для проверки предварительных цен генераций и доступности моделей используйте
[сценарий обхода с промптом и настройками](docs/model-ui-audit-prompt.md).
Агент или тестировщик выбирает модели, заполняет тестовые параметры и читает
расчёт без запуска генераций. Отчёт различает отсутствие оценки, расходный
тариф, недостающие входы, неподдерживаемые параметры и недоступные маршруты.
Сценарий требует отдельного тестового чата и резервного сохранения черновиков.
Это документированная ручная проверка; встроенная кнопка аудита и автоматический
исполнитель пока не реализованы. Успешный расчёт не подтверждает исполнение задачи.

Vue-студия поддерживает account-scoped проекты и чаты: создание, поиск,
переименование, перенос чата и архивирование. При регистрации создаётся
основной чат; новые генерации, черновики и исходники всегда привязаны к чату.
Исторические записи без привязки доступны в разделе «Без чата», а общая
история результатов — в разделе «История».

## Модули

- `public/` — страница, HTTP-мост и стили веба.
- `src/server/` — конфигурация, HTTP API, статика и события SSE.
- `src/auth/`, `src/database/`, `src/billing/` — OAuth, PostgreSQL и нативные кредиты.
- `config/native-prices.json` — версионированные пользовательские цены, первоначально пустые.
- `src/services/` — прикладные сервисы генерации и контента, контролы бота и Telegram transport.
- `src/providers/kie/` — клиент протокола Kie.
- `src/media/` — прикладной контракт медиа и адаптер; не часть библиотеки провайдера.
- Остальные `src/` — собственная копия каталога, очереди, хранения, расчётов и браузерных компонентов прототипа. Они больше не читаются из Windows-проекта и развиваются независимо.
- `test/` — проверки сервиса, бота и границ модуля.
- `data/service/` — локальные служебные данные и совместимость со старыми файлами, исключены из Git. В общем debug-окружении новые медиафайлы хранятся в приватном S3.

## Перенос

Для переноса сервиса используйте Dockerfile из корня с контекстом `.`. Образ содержит server.js, package.json, зависимости, src/, public/ и config/native-prices.json; desktop/, секреты и данные исключены. Установите зависимости командой выше. Абсолютных привязок к исходному проекту и зависимости от Electron нет.

Перед переносом существующих данных остановите сервис. Сохраняйте PostgreSQL, S3 и `data/service/` вместе. Старый JSON-workspace доступен администратору отдельно. Для чистой установки каталог данных не нужен. Секретный `.env` настраивается отдельно на сервере; образец — `.env.example`. Не включайте его в публичные архивы или Git.

После входа без ключа Kie доступны интерфейс и черновики; генерация выключена.
Для пользовательской генерации нужны опубликованный тариф и достаточный баланс.
В аккаунтном режиме Telegram поддерживает привязку через одноразовую ссылку; запуск требует настроенного токена. [Настройки и команды бота](docs/web-and-telegram.md).

## Docker

Из этой папки: `docker compose up -d --build`. Полная изолированная проверка: `docker compose --profile test run --build --rm tests` (Vue и backend-тесты с настоящей PostgreSQL).
Перед запуском контейнера остановите локальный Node-сервис: порт и данные у них общие, одновременно запускать их нельзя. Нужен локальный `.env` (можно скопировать `.env.example`). Секреты и данные не входят в образ; данные подключены из `data/service/`. Переменные `MEDIA_S3_*` из `.env` автоматически передаются web-контейнеру; Codex-sidecar их не получает.

Проверить: `docker compose ps` и http://127.0.0.1:3000/api/health.
Штатная остановка: `docker compose down` — данные сохраняются.
После изменения `.env`: `docker compose up -d --force-recreate`.
Контейнер использует системную блокировку `data/service/service.lock`: файл остаётся после остановки, но не препятствует следующему запуску контейнера. Перед локальным запуском Node с тем же хранилищем проверьте отсутствие контейнера, затем удалите файл блокировки.

Новые пользовательские исходники и результаты получают UUID и сохраняются через
единый `ContentService` в приватный S3 под ключом
`accounts/<account-id>/content/<asset-uuid>`. Для разового перехода старых данных
используйте `pnpm migrate:content`, для безопасной сверки БД с S3 —
`pnpm audit:content`. Обе команды входят в Docker-образ; аудит ничего не удаляет.

Журнал всей цепочки: [generation-logging](docs/generation-logging.md).

## Windows-приложение

Текущий проект развивает веб-продукт. `desktop.7z` оставлен архивом; команды `start:desktop` и `pack:desktop` требуют отдельного восстановления исходников.

На хостинге: корень репозитория, собственный Dockerfile; порт MEDIA_PORT или PORT, по умолчанию 3000. Для внешнего домена задайте MEDIA_PUBLIC_ORIGIN=https://ваш-домен. Корневой образ запускает веб и встроенный Codex worker; на Bothost после нового деплоя нужен один вход `codex login --device-auth` в терминале приложения. Авторизация хранится в /app/data/codex-auth. [Подключение Codex на Bothost](docs/codex.md).
