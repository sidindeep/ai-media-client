# Встроенный монтаж Remotion

Контракт от 2026-10-01. Владелец: модуль веб-монтажа.
Система: authenticated Vue App → MovieEditor → React bridge → Remotion
composition → Web Renderer → локальный MP4. История аккаунта остаётся внешним
read model; доступ к медиа проверяет существующий account-scoped content API.

## Ответственность и данные

- Вход `/app/movie`, пункт «Создать ролик». Подключение ленивое: React и
  Remotion загружаются при открытии редактора.
- `web/src/remotion/model.mjs` — источник ограничений и расчёта кадров:
  Общие ограничения config/movie-editor.json: 30 fps, до 20 сцен, фото/титры
  1–30 секунд, видео до 600 секунд, общий монтаж до 600 секунд с учётом перекрытий.
- Сцена: id, kind (title/image/video), src, title, seconds, name.
  Допустимые src: object URL и собственные `/api/` маршруты;
  внешние URL не принимаются. Пользовательский код не исполняется.
- MovieEditor владеет временным монтажом, object URL входных файлов и MP4.
  При правках старый MP4 инвалидируется, при удалении/выходе URL освобождаются.
  Экспорт блокирует редактирование; закрытие страницы отменяет активный рендер.
- Видео обрезается длительностью сцены; изображения и титры занимают всю сцену.
  Переход — перекрытие до 15 кадров (0,5 секунды), ограниченное половиной
  соседних сцен. Входящая сцена накладывается на непрозрачную исходящую без
  затемнения в фон; звук обоих клипов плавно смешивается. Материалы вписываются
  без растяжения; исходная длительность каждой сцены сохраняется.
- Музыка ограничена длительностью композиции. Звук клипов можно отключить.
- Сохранения монтажей, серверной истории экспорта и серверной очереди рендера
  нет. AI-план использует существующее текстовое задание и биллинг Codex.

HTML Vue приложения разрешает connect-src blob:, worker-src self/blob: и script-src wasm-unsafe-eval
для локального декодирования файлов/комплектных кодеков. CSP прочих поверхностей
не меняется; внешние соединения, включая телеметрию Remotion, запрещены.

## Границы и ошибки

Скачать предпросмотр: record-preview.ts записывает Player от кадра 0 до ended
через getDisplayMedia → Region Capture cropTo(#movie-composition) → MediaRecorder.
Запись стартует только после успешной обрезки в текущей вкладке, без захвата
остальной страницы или органов управления. Нужен Chrome/Edge и явный выбор вкладки;
для монтажа со звуком обязателен audio track. MP4 при доступном MediaRecorder codec,
иначе WebM с верным MIME/расширением. Автоскачивание и ссылка на повтор, без upload.
Старый кадр/состояние воспроизведения восстанавливаются; отмена, закрытие захвата,
ошибка и выход освобождают все tracks/recorder/listeners. Монтаж закрыт для правок
на время записи; экспорт Web Renderer и снимок черновика не задействованы.
В isPlayer composition использует Html5Video/Html5Audio, сохраняя длительности,
титры и volume-переходы. Web Renderer использует прежние @remotion/media Video/Audio.
Это разделяет нативное воспроизведение/запись и кадровое декодирование экспорта.

`mountPreview/update/dispose` — lifecycle React-острова внутри Vue.
`exportMovie` проверяет WebCodecs/кодеки, принимает AbortSignal и прогресс,
возвращает Blob MP4 H.264/AAC. Кэш декодированных медиа ограничен 256 МБ.
prepare-media.mts перед декодированием последовательно читает каждый уникальный
исходник полностью в Blob (до 100 МБ на файл), с credentials=same-origin и AbortSignal.
Таймаут скачивания 180 секунд на файл; локальные blob URL используются только
в snapshot экспорта, без изменения ссылок черновика, и освобождаются в finally.
Предпросмотр размонтируется перед экспортом и восстанавливается после завершения,
ошибки или отмены. Рендер не читает API/S3 по кадрам; ожидание кадра ограничено
120 секундами. Лимиты экспорта заданы в config/movie-editor.json.
Подготовка отображает счётчик файлов, затем обычные проценты рендера. Тесты
проверяют дедупликацию, cleanup, отмену, медленные полные скачивания и экспорт
без повторных/Range-запросов к API.
Готовый файл принадлежит пользователю и скачивается с его устройства.
Перед экспортом `media-check.mts` проверяет canDecode основных видео/аудиотреков
через Mediabunny 1.56.1, совпадающий с зависимостью Remotion. Читатели ограничены
1 МБ кеша, освобождаются после проверки/отмены; повторные src проверяются один раз.
Беззвучные клипы не требуют аудиодекодера. Неподдерживаемые треки дают сообщение
с номером сцены и способом исправления без вывода URL. Импорт не транскодирует.
Входные локальные файлы ≤100 МБ сохраняются через /api/movie/asset в существующем
модуле материалов, приватный S3 либо локальный fallback исходников аккаунта.

## Импорт удалённых источников

`src/services/movie-sources.js` владеет адаптерами Yandex public resources,
Google Drive v3 и прямого HTTPS/JSON/HTML/text списка. Публичные папки
обходятся рекурсивно с пагинацией (50 запросов, 5 уровней). Google требует
server-only MEDIA_GOOGLE_DRIVE_API_KEY; OAuth закрытых папок не подключён.
`fetchPublicResult` из content-service проверяет DNS и закрепляет публичный
IP; каждый redirect проверяется повторно. Google resource keys отправляются
служебным заголовком и не пересылаются при redirect.

Authenticated same-origin POST `/api/movie/sources/list` принимает url/limit,
возвращает files(id,name,type,size), skipped/truncated. Ticket хранится только
в памяти серверного процесса, привязан к user.id, живёт 30 минут; новый список
того же пользователя инвалидирует предыдущий. POST `/api/movie/sources/file`
принимает ticket id, возвращает байты, не произвольный клиентский download URL.
Один запрос импорта на пользователя, два одновременно на сервер, до 2000 tickets.
Лимит файла 100 МБ проверяется по заголовку и фактически прочитанным байтам,
MIME и сигнатуры подтверждаются до выдачи. HTTP timeout 60/180 секунд.
Уход/отмена клиента прекращает HTTPS-запрос. Маршруты публикуют только
очищенный фиксированный MOVIE_SOURCE_FETCH в ai_logger.

MovieEditor загружает список/файлы последовательно через accountHeaders,
создаёт фото по 5 секунд и видеосцены полной длительности. video-duration.mts
читает длительность трека через Mediabunny для импорта, локальных файлов и
истории. При неизвестной длительности или видео длиннее 600 секунд добавление
отклоняется с явным сообщением, без обрезки. «Весь клип» восстанавливает длительность
уже сохранённой сцены; прежние пользовательские длительности сами не меняются. На время загрузки правки
и экспорт блокируются; ошибки отдельных файлов не отменяют остальные.
Сводка отображает добавленные/пропущенные файлы и неполный импорт. Лимит
300 МБ за импорт на клиенте. Отмена сохраняет загруженное в аккаунте и черновике.
Переход между разделами сохраняет редактор через KeepAlive; обновление страницы
восстанавливает серверный черновик. Фонового мониторинга папок и транскодинга нет.

Authenticated POST `/api/movie/errors` принимает только фиксированные
MOVIE_RENDER_FAILED/MOVIE_PREVIEW_FAILED/MOVIE_PLAN_INVALID; другие значения отклоняются.
Сервер публикует очищенную диагностику ai_logger без пользовательских данных.
Экспорт сохраняет этап support/media/render/output и одну фиксированную категорию
NETWORK/DECODE/ENCODE/TIMEOUT/MEMORY/SECURITY/UNSUPPORTED/UNKNOWN через export-error.mts.
Неизвестные сообщения сводятся к UNKNOWN, без исходного текста/stack/URL. UI показывает
идентификатор, reportMovieError передаёт optional failure; сервер проверяет полный
allowlist до логирования и записывает его только в diagnostic.description. Прежние
запросы без failure остаются совместимы. Отмена и ошибки MovieMediaError сохраняют
прежнее поведение. Проверка включает отказ чтения медиа, безопасную причину и повтор.
Ошибка неподдерживаемого браузера показывается локально и не является сбоем
генеративного провайдера. Версия библиотеки фиксируется одинаково во всех
пакетах Remotion. Лицензирование описано в `docs/remotion-video-editor.md`.

## AI-план монтажа

`MovieScenario.vue` получает живой каталог/цену Codex, показывает стоимость
до запуска, отправляет kind=text через существующий submitCodex с UUID requestId
и привязкой текущего проекта/чата. Нет отдельного подключения OpenAI или обхода
кошелька/очереди. Задание и текстовый результат принадлежат аккаунту и остаются
в существующей истории. С 2026-10-01 опубликованный тариф — 10 кредитов за запрос,
включая GPT-6-Sol и GPT-6-Luna; источник цены — config/native-prices.json.
В модель идут сценарий ≤8000 символов, ID, названия и
подписи материалов, без src URL или байтов фото/видео. Автоматического vision,
AI-озвучки, генерации музыки и произвольных эффектов нет.

`scenario.mjs` формирует ограниченный prompt и валидирует JSON scenes:
sourceId=null для титра либо точный ID из исходного набора, title≤300, seconds
число в пределах типа сцены, ≤20 сцен/600 секунд. Prompt сообщает доступную
длительность видео и требует сохранить её, если пользователь не просил обрезку;
план не может удлинить видео за пределы исходной сцены. Внешние ссылки, код, лишние поля и неизвестные
материалы отклоняются до атомарного применения. Повторения материалов получают
разные ID сцены. Дубликаты object URL не отзываются при удалении одного экземпляра.
MovieEditor хранит одну резервную копию предыдущего монтажа для undo.

Правки/импорт/экспорт блокируются на время ожидания AI. Poll 1.5 секунды, предел
ожидания 10 минут; остановка/выход не отменяет серверное выполнение и биллинг.
После сетевой ошибки UUID остаётся для проверки статуса без повторной отправки.
Новый сценарий явным действием создаёт новое задание. При применении после паузы
удалённые источники проверяются повторно. Ошибка ответа вызывает фиксированный
MOVIE_PLAN_INVALID через /api/movie/errors, без вывода содержимого в диагностику.
Невалидный AI-план не отменяет оплату успешного текстового ответа провайдера.

## Проверка сборки системы

## Черновики роликов (2026-10-01)

Модуль src/services/movie-drafts.js владеет namespace movie-drafts в media_records;
существующая схема, без миграции. GET/PUT /api/movie/draft?projectId=UUID возвращает
и сохраняет один черновик проекта, без projectId — черновик аккаунта. PUT принимает
{draft,revision}, CAS возвращает 409 при устаревшей версии. Владелец определяется
сессией; project проверяется Workspaces, каждый media URL проверяется через
Content или аккаунтный MediaService. В JSON разрешены только внутренние ссылки;
blob/data/внешние URL не сохраняются. Content владеет байтами, MovieDrafts — монтажом.
HTTP-сервис черновиков подключается и пересоздаётся вместе с аккаунтными сервисами
после отложенного старта БД и переподключения. При ошибке начальной загрузки
редактор предлагает повторить загрузку; правки закрыты до восстановления черновика.
Автосохранение 400 мс, последовательные записи, статус/ошибка/повтор. Материал
добавляется после приватного сохранения и сразу сохраняется с монтажом.
Сценарий, модель и pending requestId/sources переживают reload без повторной оплаты.
Готовый экспорт не сохраняется автоматически; физическое удаление материалов
и GC не добавляются. Module/API tests проверяют изоляцию, CAS и устойчивые ссылки;
browser E2E — импорт, переключение раздела, reload и восстановление монтажа.

Диагностика импорта (2026-10-01): ai_logger получает безопасные счётчики причин
пропуска списка и этап/код/HTTP-статус/сетевой код ошибок скачивания, включая
SourceError и отмену соединения. URL, имена и аккаунты исключены. В UI ошибки
файлов сохраняются списком до следующего импорта; лимит 300 МБ обозначается явно.
Тикеты разных импортов одного владельца независимы: новый list не удаляет старые,
download проверяет owner и TTL 30 минут; общий предел 2000 тикетов сохранён.

Unit: ограничения, последовательность кадров, запрет внешних медиа.
Container E2E: авторизованный вход, титр, реальный экспорт MP4 и декодирование
размеров/длительности, добавление локального PNG, клипа и PCM-музыки, повторный
экспорт и проверка длительности. TEST_DATABASE_URL используется только
изолированным browser-tests профилем. Рабочий DATABASE_URL не меняется.
