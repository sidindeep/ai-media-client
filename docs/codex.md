# Codex CLI в вебе

В форме генерации сначала выбирается провайдер: Kie.ai для изображений/видео
или Codex CLI для изображений и текста. У Codex отдельный тип результата:
«Изображение» (по умолчанию) или «Текст». Перед запуском видны провайдер, модель, уровень
рассуждения, скорость и цена. Уровни ползунка берутся из каталога выбранной
модели. Fast передаёт CLI `service_tier="fast"`; обычная скорость использует
стандартный режим. Доступность модели и Fast зависит от серверного аккаунта.

Все авторизованные пользователи работают через один серверный аккаунт Codex
и оплачивают запросы внутренними кредитами. Вводить свой аккаунт Codex им
не нужно. Запросы изолированы по пользователям; доступ к токенам входа и
командам CLI через форму не предоставляется. В режиме изображения Codex
вызывает встроенный генератор; веб показывает PNG и кнопку скачивания.
Текстовый ответ без PNG не считается успехом: резерв возвращается.
Видео через Codex не подключено.

## Тарифы

В `config/native-prices.json` (либо `MEDIA_PRICING_FILE`) нужны отдельные
записи `models["codex:<model>:<effort>:<speed>"].baseUnits`.
`speed`: `standard` или `fast`; уровни и модели — из `config/codex-models.json`.
1000 единиц соответствуют одному внутреннему кредиту. По решению владельца
от 2026-09-18 все 54 сочетания модели/уровня/скорости Codex стоят столько же,
сколько Nano Banana 2 Lite: **4 внутренних кредита за запрос** (`baseUnits: 4000`).
Это временная фиксированная цена, без надбавок за Fast или уровень рассуждения.
Она не рассчитывается из фактического расхода лимитов серверного аккаунта.
Без записи тарифа кнопка запуска закрыта, API также отклоняет запрос.
После изменения цен необходимо пересобрать/перезапустить веб-сервис.

Перед отправкой резервируется цена запроса; успешный результат списывает
резерв ровно один раз. Подтверждённый отказ возвращает резерв. При потере
связи или неизвестном результате резерв остаётся до проверки; автоматический
повтор генерации запрещён. Пользователь видит кнопку проверки статуса.
Администратор может сверить неизвестный результат через существующий
`POST /api/admin/reconcile` с `jobId` из ссылки операции кошелька:
`codex:<accountId>:<requestId>`, результатом и обязательным свидетельством.

## Docker и вход на хосте

### Bothost: один контейнер из корневого Dockerfile

Корневой `Dockerfile` содержит Codex CLI и автоматически включает встроенный
worker на `127.0.0.1:3210`. Второй сервис, внешний образ `llm-providers:local`
и Docker Compose для этого варианта не нужны. В настройках Bothost должна
быть включена опция «Использовать собственный Dockerfile». После обновления
кода выполнить новый деплой со сборкой образа, а не только рестарт процесса.

Сохранить существующие DATABASE_URL, OAuth и Kie настройки. Если заданы
`MEDIA_CODEX_URL=http://codex:3210` или `MEDIA_CODEX_EMBEDDED=false`, удалить эти
переопределения: адрес отдельного Compose-сервиса на Bothost не используется.
Dockerfile задаёт `MEDIA_CODEX_EMBEDDED=true`, `CODEX_HOME=/app/data/codex-auth`.
Каталог `/app/data` должен сохраняться между деплоями средствами хостинга.
Веб использует MEDIA_PORT, затем PORT, затем 3000; внутренний порт в панели
Bothost должен соответствовать этому значению.

После деплоя открыть терминал приложения **в панели Bothost** и выполнить:

```sh
codex login --device-auth
codex login status
```

Первая команда выдаст ссылку и код: открыть ссылку на своём компьютере,
войти в серверный аккаунт Codex и ввести код. Дождаться успешного завершения
команды в терминале; вторая должна подтвердить `Logged in using ChatGPT`.
Авторизация локального Docker сама на Bothost не переносится. Пользователям
веба входить в Codex не нужно; для запроса достаточно 4 внутренних кредитов.

В журнале старта появится `Codex worker ready on loopback`. Worker не слушает
внешний интерфейс; процесс CLI получает ограниченный набор переменных среды
без DATABASE_URL, OAuth-секретов и KIE_API_KEY.

### Локальный Compose: два контейнера

Сначала собрать базовый `llm-providers:local` по инструкции
`../llm_providers/docs/docker.md`. Затем из корня этого проекта:

```powershell
docker compose up -d --build
docker compose exec codex codex login --device-auth
docker compose exec codex codex login status
```

Команда входа показывает ссылку и одноразовый код в терминале хоста.
Открыть ссылку можно в браузере своего компьютера: браузер на сервере
не нужен. После подтверждения дождаться успешного завершения команды.
Том `llm-providers_codex-auth` сохраняет вход при пересоздании контейнера.
Имя уже существующего тома переопределяется `MEDIA_CODEX_AUTH_VOLUME`.
На другом хосте нужно подготовить том и выполнить вход заново.

Веб обращается к worker по приватной сети Compose, порт worker не опубликован.
Не публиковать его наружу: аутентификацию, проверку владельца и кошелька
выполняет веб. Worker принимает один активный запрос и ограничивает его
тремя минутами для текста и пятью для изображения; при занятости резерв возвращается. Его временный кеш результатов
живёт до часа и теряется при перезапуске; подтверждённые вебом результаты
сохраняются в PostgreSQL, а PNG — в `data/service/codex-images/<account>/<request>.png`
(внутри `MEDIA_DATA_DIR`). PNG выдаётся только после проверки владельца задания.
Неопределённые задания после перезапуска требуют
сверки, а не повторного запуска.

Проверки: `node --test test/codex.test.js test/accounts.test.js` и скрытый
UI smoke из runbook. Тестовые тарифы используются только в изолированной БД.

Для изображения включены `image_generation`, `code_mode` и `code_mode_host`;
shell, браузер и прочие интеграции остаются отключёнными. Codex CLI 0.155.0
не включает PNG в JSONL stdout: worker берёт файл только из каталога
`generated_images/<thread_id>` по событию `thread.started`, а не по тексту
модели. После передачи PNG временный каталог изображения удаляется.
Генератор использует общий лимит аккаунта Codex; [официальная документация](https://learn.chatgpt.com/docs/image-generation).
