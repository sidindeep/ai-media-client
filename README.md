# AI Media Web + Telegram

Самостоятельный переносимый модуль веб-интерфейса и Telegram-бота. Веб и Telegram находятся в корне репозитория. Windows-приложение изолировано в desktop/ и не требуется для запуска сервиса.

Веб поддерживает аккаунты Google/VK, отдельную историю и баланс нативных кредитов,
роли пользователя и администратора. [Настройка БД, OAuth и цен](docs/accounts-and-credits.md).
Покупки кредитов и балансировка провайдеров пока не подключены.

## Запуск

Нужны Node.js 22.9+, pnpm и PostgreSQL. Сначала настройте `.env` по
`.env.example`: DATABASE_URL, публичный HTTPS origin и OAuth-приложения.
Для прежнего локального режима владельца доступен явный MEDIA_AUTH_ENABLED=false
только на loopback и без публичного origin. Выполняйте команды из этой папки:

```powershell
pnpm install --ignore-workspace --frozen-lockfile
pnpm start
```

Открыть http://127.0.0.1:3000 — это публичная главная AI Media Client. Главная и новая Vue-студия на `/app` работают в одной SPA-оболочке: после первоначальной загрузки переходы между ними не перезагружают документ и сохраняют данные студии в памяти. Внутренний обзор доступен на `/app/home`, а прежняя DOM-студия сохранена на `/legacy`. Остановить — Ctrl+C. Разработка: `pnpm dev`.

Для web-фронтенда: `pnpm build:web` собирает Vue/Vite-приложение в `public/vue`, `pnpm check:web:vue` проверяет TypeScript. Backend и API остаются общими для обоих интерфейсов.
Проверки: `pnpm check` и `pnpm test`.

Vue-студия поддерживает account-scoped проекты и чаты: создание, поиск,
переименование, перенос чата и архивирование. Выбранный чат передаётся в
генерации, черновики и материалы; системный чат «Ранее» показывает прежнюю
историю без удаления существующих результатов.

## Модули

- `public/` — страница, HTTP-мост и стили веба.
- `src/server/` — конфигурация, HTTP API, статика и события SSE.
- `src/auth/`, `src/database/`, `src/billing/` — OAuth, PostgreSQL и нативные кредиты.
- `config/native-prices.json` — версионированные пользовательские цены, первоначально пустые.
- `src/services/` — прикладной сервис генерации, контролы бота и Telegram transport.
- `src/providers/kie/` — клиент протокола Kie.
- `src/media/` — прикладной контракт медиа и адаптер; не часть библиотеки провайдера.
- Остальные `src/` — собственная копия каталога, очереди, хранения, расчётов и браузерных компонентов прототипа. Они больше не читаются из Windows-проекта и развиваются независимо.
- `test/` — проверки сервиса, бота и границ модуля.
- `data/service/` — локальные данные сервиса, исключены из Git.

## Перенос

Для переноса сервиса используйте Dockerfile из корня с контекстом `.`. Образ содержит server.js, package.json, зависимости, src/, public/ и config/native-prices.json; desktop/, секреты и данные исключены. Установите зависимости командой выше. Абсолютных привязок к исходному проекту и зависимости от Electron нет.

Перед переносом существующих данных остановите сервис. Сохраняйте PostgreSQL и `data/service/` вместе. Старый JSON-workspace доступен администратору отдельно. Для чистой установки каталог данных не нужен. Секретный `.env` настраивается отдельно на сервере; образец — `.env.example`. Не включайте его в публичные архивы или Git.

После входа без ключа Kie доступны интерфейс и черновики; генерация выключена.
Для пользовательской генерации нужны опубликованный тариф и достаточный баланс.
Telegram пока работает только в локальном режиме владельца; в режиме аккаунтов
он отключён до реализации привязки. [Настройки и команды бота](docs/web-and-telegram.md).

## Docker

Из этой папки: `docker compose build`, затем `docker compose up -d`.
Перед запуском контейнера остановите локальный Node-сервис: порт и данные у них общие, одновременно запускать их нельзя. Нужен локальный `.env` (можно скопировать `.env.example`). Секреты и данные не входят в образ; данные подключены из `data/service/`.

Проверить: `docker compose ps` и http://127.0.0.1:3000/api/health.
Штатная остановка: `docker compose down` — данные сохраняются.
После изменения `.env`: `docker compose up -d --force-recreate`.
После аварийной остановки проверяйте отсутствие прежнего процесса/контейнера перед удалением `data/service/service.lock`, как при обычном запуске.

Журнал всей цепочки: [generation-logging](docs/generation-logging.md).

## Windows-приложение

Исходники, зависимости, тесты и сборки находятся в [desktop/](desktop/README.md). Установка: `pnpm --dir desktop install --frozen-lockfile`. Запуск: `pnpm start:desktop`. Проверки: `pnpm check:desktop`, `pnpm test:desktop`. Сборка: `pnpm pack:desktop`; единственный EXE: `desktop/dist/queue-header/win-unpacked/AI Media Client.exe`.

На хостинге: корень репозитория, собственный Dockerfile; порт MEDIA_PORT или PORT, по умолчанию 3000. Для внешнего домена задайте MEDIA_PUBLIC_ORIGIN=https://ваш-домен. Корневой образ запускает веб и встроенный Codex worker; на Bothost после нового деплоя нужен один вход `codex login --device-auth` в терминале приложения. Авторизация хранится в /app/data/codex-auth. [Подключение Codex на Bothost](docs/codex.md).
