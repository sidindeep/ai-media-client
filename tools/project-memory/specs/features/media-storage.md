# Исходники, повтор и результаты

Статус: этот документ описывает legacy-совместимость. С 2026-09-22 все новые
файлы веб-сервиса проходят через `ContentService`, получают UUID и сохраняются в
приватный S3 по ключу `accounts/<account-id>/content/<asset-uuid>`. PostgreSQL
хранит каталог, владельца, SHA-256, состояние, устойчивое задание и связь с
генерацией. Старые hash-ref, локальные пути и прежние S3-ключи остаются только
для чтения и миграции.

Цель: локальные исходники переживают перезапуск, а результаты сохраняются без перезаписи и фиктивного успеха. Актор — пользователь, выбирающий файлы и папку.

## Исходники и повтор

Assets.save принимает непустые байты, вычисляет SHA-256, пишет уникальный .part и создаёт ссылку на файл с именем hash. Существующий hash переиспользуется. Возвращается ref вида https://local-assets.invalid/<sha256>, имя для отображения, MIME и размер. Имя пользователя не становится путём хранения.

Перед каждой задачей рекурсивно обходится input. Для локального ref требуются metadata, существующий файл и совпадение SHA-256. Одинаковый ref загружается один раз в рамках задачи (кэш Promise); следующая генерация загружает его заново. Обычные внешние ссылки проходят без скачивания в локальный архив. Повтор восстановления настроек не равен повторной отправке старого POST.

## Потоковый приём веб-исходников

Codex принимает ссылки `content:<UUID>` из ContentService и прежние
`https://local-assets.invalid/<sha256>`. Общая проверка запроса веба и worker
разрешает оба формата, сохраняя лимит 10 исходников. Перед резервированием
кредитов billing читает content через `content.read(account, id)` с проверкой
доступа владельца и передаёт байты worker. Недоступный исходник не запускает
генерацию и не создаёт резерв. Регрессия проверяется в `test/codex.test.js`.

HTTP-загрузка передаёт поток в `ContentService`, не собирая весь файл в Buffer.
Размер проверяется во время передачи и ограничен настройкой загрузки (по
умолчанию 64 МиБ). При известном Content-Length резервируется объявленный
размер, иначе полный лимит запроса; общий бюджет одновременно принимаемых
байтов по умолчанию 256 МиБ. Превышение отдельного лимита отклоняется, а
переполнение общего бюджета даёт 429. Поток проходит через счётчик размера и
SHA-256 во временный `.stage`/`.part`, который удаляется при обрыве или ошибке.

Устойчивое задание сохраняет файл в приватном S3, затем сверяет размер и хеш
прочитанного объекта до `ready`. Worker обрабатывает ограниченное число файлов
параллельно (по умолчанию три), поэтому зависший файл не задерживает все
остальные. Тестовый поток 25 × 16 МиБ завершился без остаточного staging;
это проверка бесплатного стенда, а не реального S3.

Общая квота `content-staging` ограничивается `MEDIA_CONTENT_STAGING_MB` (по
умолчанию 1024 МиБ). Она учитывает уже существующие файлы при старте, текущие
потоковые загрузки и временные части скачиваемых результатов. Резервирование
байтов происходит до записи каждого блока; при превышении квоты операция
останавливается, частичный файл удаляется, а устойчивое задание результата
остаётся доступным для повтора. Сохранённый в S3 файл освобождает локальную
квоту только после удаления staging-копии. Оставшиеся после аварийного
завершения файлы учитываются при следующем запуске, автоматически не удаляются.
HTTPS-соединение для результата использует проверенный публичный DNS-адрес и
исходное имя хоста для TLS; каждый редирект проверяется заново.

## Результаты

saveResults разрешён только для success. Одновременные сохранения одной записи объединяются. Если папка не выбрана, запрашивается выбор; отмена не отмечает файлы сохранёнными. URL берутся из resultJson.resultUrls.

Для каждого URL существующий локальный файл пропускается, отсутствующий скачивается заново. После каждого файла localFiles сохраняется отдельно; частичный успех переживает ошибку следующего файла. downloadError отделён от state генерации.

download допускает HTTPS и HTTPS после перенаправления, поддерживаемые image/video MIME либо octet-stream с допустимым расширением URL. Таймаут 300 секунд. Поток идёт во временный .part; пустое тело отклоняется. Итоговое имя случайное, COPYFILE_EXCL запрещает перезапись. Временный файл удаляется и при ошибке.

Для веб-сервиса сохранение всех успешных результатов в S3 обязательно и не
зависит от пользовательского `autoSave`; устойчивое задание возобновляется после
перезапуска. Настройка `autoSave` сохраняет прежний смысл только для legacy и
Windows-потоков.

Источники веба: `src/services/content-service.js`, `src/assets.js`,
`src/services/media-service.js`, `src/services/codex-billing.js`,
`src/server/http.js`. Проверки: `test/content-service.test.js`,
`test/assets.test.js`, `test/downloads.test.js`, `tools/load-test/upload.cjs`.
Исторические ссылки на `main.js`/`renderer.js` относятся к desktop, которого
нет в текущем checkout; они не служат доказательством текущего поведения.
