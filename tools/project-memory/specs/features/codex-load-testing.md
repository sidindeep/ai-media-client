# Контракт исследования нагрузки Codex

Дата: 2026-09-18. Пользователь запросил изучение, затем запись плана по GI.
Статус: планирование; генерации и изменение runtime этим шагом не выполнялись.

Канонический [план, этапы и Definition of Done](../../../../docs/codex-load-test-plan.md)
находится в продуктовой документации. Эта запись — компактный контракт измерений,
а не хранилище результатов. [Интеграция Codex](../integration-contracts/llm-providers.md).

## Инварианты

- Измерять текст и изображения отдельно на фиксированных настройках и корпусе.
  Учитывать окружение и фон общего серверного аккаунта; не переносить локальные
  показатели на хостинг без измерений.
- Успех означает доступный пользователю сохранённый результат, а не приём POST.
  Для изображения проверять выдачу PNG. Учёт включает fail, unknown и незавершённые.
- Один requestId соответствует одной попытке. Не повторять генерацию при потере
  связи; сверять результат и резерв по существующему заданию.
- Ограничивать запуск числом отправок, временем и бюджетом. При stop прекратить
  новые отправки и учесть уже принятые; не объявлять их автоматически отменёнными.
- Usage без данных остаётся неизвестным; CLI-токены и внутренние кредиты
  не являются полной оценкой расхода лимита инструмента изображений.
- Проверять память всего дерева процессов, удерживаемые PNG/Base64, TTL,
  постоянный диск и остатки ошибок. Длительный тест должен пересечь часовой TTL.
- Небольшой пилот устанавливает предварительный диапазон, не достоверный p95
  и не безопасную рабочую мощность. Последняя требует длительного подтверждения.

## Карта доказательств и статус

- `src/services/codex-worker.js`: неограниченный запуск CLI, Map результатов,
  Base64, очистка завершённых записей по createdAt только при запросах к заданиям.
- `src/services/codex-billing.js`: PostgreSQL, файлы PNG, резервы, опрос и unknown.
- `src/services/codex-images.js`, `src/services/codex-usage.js`: валидация PNG и usage.
- `test/codex.test.js`: параллельность на заглушке; это не нагрузочное доказательство.
- Будущие материалы запуска: `artifacts/load-tests/<run-id>/` вне Git.

Измеренная мощность отсутствует. Следующий этап — A1–A3 канонического плана:
паспорт, измеритель и наблюдаемость. Реальные запуски не считать выполненными
до появления отчёта с идентичностью окружения и сверкой отправок.

Позднее в той же сессии выполнен отдельный [пилот транспортов](codex-transports.md)
на 12 разрешённых генерациях. Он сравнивает адаптеры напрямую, без веб-кошелька
и часового кеша, и не закрывает этапы сквозного/длительного плана.

## Нагрузка до отказа (2026-09-18)

Пользователь уточнил: измерять Codex, а не HTTP, и разрешил нагрузку «на максимум».
Выполнены отдельные короткие ступени app-server с изображениями, GPT-5.5/medium/Fast,
через приватный тестовый worker с часовым кешем внутри текущего локального Docker.
Канонический [отчёт и команда](../../../../docs/codex-capacity.md).
Все 255 запросов ступеней 1–128 дали PNG; пик волны 128 — 2,058 результата/с,
среднее 49,2 с, p95 57,8 с. Ступень 256 завершилась 256 unknown через ~15 секунд.
Повторы не отправлялись. Полный аккаунтный расход unknown неизвестен.

OOM и рестарт контейнера исключены по Docker/cgroup. Вероятен 15-секундный RPC
timeout с общей остановкой app-server; метод/причина break сейчас не логируются,
поэтому точный триггер не доказан. Это граница текущего адаптера, не найденная
квота Codex и не подтверждённый физический предел сервера.
Всего 511 отправок в этом исследовании, 255 успешных и 256 unknown.
Доказательства: `artifacts/load-tests/capacity-image-2026-09-18T16-27-33-018Z/`
и `artifacts/load-tests/capacity-image-2026-09-18T16-32-21-820Z/`.

Длительная безопасная мощность всё ещё неизвестна: при наблюдаемом размере PNG
и 2,058 результата/с часовой Base64-кеш оценивается примерно в 10 ГиБ без остальных
данных. Не выдавать арифметические 494 пользователя с запросом раз в 4 минуты
за гарантированную вместимость. HTTP-тест по уточнению пользователя остановлен;
его показатели для выводов не используются. Runtime в этом измерении не изменялся.
