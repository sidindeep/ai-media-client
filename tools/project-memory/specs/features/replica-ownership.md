# Владение задачами при нескольких репликах

Статус: реализованы executor и веб-реплики. По решению владельца от 2026-09-30
глобальная блокировка PostgreSQL снята; независимые executor могут запускаться
на нескольких ПК с общей БД. Распределённое владение задачами не реализовано.

## Роли и инварианты

- `executor` восстанавливает и выполняет очереди Kie, Codex и
  RouterAI, задания сохранения контента, Telegram polling и платёжный outbox.
  `web` обслуживает чтение и SSE, а все записи и загрузки потоково направляет
  владельцу по внутреннему адресу. `single` совмещает роли.
- Каждый экземпляр держит файловую блокировку своего каталога данных.
  PostgreSQL lock `18274693`, выделенное соединение владельца, его таймер и
  отказ `EXECUTOR_BUSY` удалены из запуска и повторного подключения.
- Старый ключ владения `18274693` не используется транзакциями конфигурации.
  Конфигурация преобразования параметров использует `18274694`; её подготовка
  и активация не ждут завершения работающего executor.
- Все реплики используют одну БД и доступный по одинаковому пути общий каталог
  staging. Изменения аккаунтов передаются через PostgreSQL LISTEN/NOTIFY,
  поэтому SSE на другой веб-реплике видит обновления. Авторизация и Origin
  проверяются с обеих сторон пересылки.
- При недоступном владельце чтение остаётся доступным, запись получает 503.
  После восстановления безопасная `queued` задача может стартовать;
  `submitting` без подтверждённого ID провайдера становится `unknown` и не
  отправляется платно автоматически. Гарантия единственного исполнителя между
  независимыми executor отсутствует: фоновые операции могут пересекаться.

Общий бюджет соединений включает пулы всех реплик и LISTEN. Для нескольких
исполнителей потребуются task lease/fencing, общий лимитер и межузловой
staging; этот контракт их не обещает.

Для Codex отрицательный результат 404 ограничен экземпляром приватного worker
(X-Codex-Worker-Instance). Перезапуск media не повторяет GET отсутствующего
задания на этом worker; другой worker может восстановить результат из своих
файлов. До подтверждённого success/fail сохраняется unknown и денежный резерв.
Это не вводит распределённое владение или автоматический повтор генерации.
Подробности: [транспорты Codex](codex-transports.md).

Проверки: `test/replica-web.test.js` (включая запуск двух executor на одной БД),
`tools/load-test/replica-failover.cjs`, `tools/load-test/replicas-read.cjs`.
Операционный запуск: `docs/replica-ownership.md`; реализация: `server.js`,
`src/server/http.js`, `src/database/change-events.js`.

`tools/load-test/replica-lock.cjs` — историческая проверка механизма PostgreSQL,
не проверка текущего запуска приложения.
