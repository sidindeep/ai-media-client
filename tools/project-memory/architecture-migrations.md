# История архитектуры

2026-09-18: веб переходит от общего JSON-workspace к аккаунтам Google/VK,
PostgreSQL и tenant-каталогам медиа. Отдельные модули auth/database/billing,
роль admin и нативные кредитные резервы вместо выдачи провайдерского баланса
пользователям. Старый workspace сохранён как admin legacy; автоматического
переноса данных нет. Desktop не затронут. Telegram в auth-режиме выключен до
привязки аккаунтов. Откат: остановить новый сервер, сохранить БД/файлы и включить
явный локальный owner-only режим; новые аккаунты не преобразуются обратно в
старую общую историю. Контракт: specs/features/accounts-credits.md.
Проверки: 24 node:test, включая SQL/PGlite и подставные OAuth HTTP, синтаксис
и diff. Рабочая БД и живые OAuth не настроены, Docker engine недоступен.

2026-09-17: добавлен отдельный web/Telegram runtime в том же проекте. Переход
от Electron-only к общим доменным модулям и двум runtime: desktop и Node server.
Данные не мигрируются; новый каталог data/service. Браузерный bridge заменяет IPC
на ограниченный HTTP RPC, события очереди — SSE. Откат — остановить server.js;
desktop остаётся самостоятельным. Контракт: specs/features/web-telegram.md.

2026-09-17: зафиксирована текущая архитектура Electron с локальными JSON-хранилищами и внешним API Kie. Миграция продукта не выполнялась.

Исторические переходы без проверенных дат и причин не выдумываются. Будущие записи должны содержать старую/новую архитектуру, причину, сохраняемое поведение, совместимость и откат, затронутые спецификации и доказательства проверки.

2026-09-22: пользовательские файлы веб-сервиса переведены с разрозненных
локальных путей, provider URL и специальных S3-ключей на единый `ContentService`.
Новая схема v4 хранит каталог `content_assets`, tenant-safe связи
`content_links` и устойчивые `content_jobs`; каждый новый файл получает UUID и
приватный ключ `accounts/<account-id>/content/<asset-uuid>`. Причина — исключить
зависимость постоянного контента от диска экземпляра и отделить состояние
генерации от сохранения. Сохранены прежние чаты, порядок по времени и чтение
legacy-ссылок. Миграция зарегистрировала 25 доступных объектов и отметила 21
запись `missing`, ничего не удаляя; аудит не нашёл отсутствующих ready-объектов,
ошибок размера и S3-сирот. Откат: остановить сервис, сохранить PostgreSQL, S3 и
`data/service`, вернуть предыдущий код; старый код игнорирует новые таблицы, но
новые UUID-ссылки без ContentService не обслуживает. Контракт:
specs/features/content-module-plan.md и specs/features/media-storage.md.

2026-09-17: по запросу владельца веб/Telegram перемещены из web-tg/ в корень, Electron — в desktop/ вместе с исходниками, тестами, инструментами и единственным dist/queue-header. Причина: стандартный деплой корня репозитория без Electron. Форматы данных и Electron app name не менялись; data/service и локальные .env перенесены, userData сохранён. Проверено: 18 web-тестов, 50 desktop-тестов, UI smoke исходников и app.asar, pack, Docker build и health на 3000. Образ не содержит desktop/Electron. Откат структуры требует остановки сервиса и обратного переноса data/service вместе с Compose bind mount; не запускать две копии бота.
