# История генераций и синхронизация workspace

Статус: реализовано и проверено 2026-09-26. История объединяет записи Kie,
Codex и RouterAI только в пределах выбранного аккаунта. Администратор может
явно выбрать другой аккаунт; обычный пользователь видит только свой.

## Контракт чтения

- Первый снимок workspace возвращает все активные задачи отдельно от первой
  страницы неактивной истории. Неактивные записи выдаются по 50; следующие
  страницы запрашиваются явно, без загрузки всей истории при открытии студии.
- Лента выбранного чата читает собственные страницы `/api/workspace/history`
  с `chatId` (`system:recent` означает отсутствие `chatId`). Фильтр применяется
  в SQL внутри выбранного аккаунта до лимита и курсора. Поэтому старые записи
  чата доступны независимо от положения среди общих страниц аккаунта.
- Порядок страниц устойчивый: `createdAt`, namespace, id по убыванию. Курсор
  кодирует последнюю тройку и следующая страница выбирает только меньшие
  тройки. Сервер проверяет формат и длину курсора и берёт на одну запись больше
  лимита, чтобы определить наличие продолжения.
- Активные состояния исключены из страниц, но остаются в первом снимке и
  последующих изменениях. Серверный курсор времени ограничивает delta-чтение;
  клиент сливает записи по ID и выбирает более новую ревизию/состояние. При
  подгрузке старой страницы уже показанная активная или обновлённая карточка
  не должна откатываться назад.
- Представление файлов для страницы получает metadata пакетом. Наличие
  сохранённого файла подтверждается на доступе к нему, без S3 HEAD или stat
  для каждого старого вложения во время листания.

Delta-синхронизация повторно читает видимые активные задачи всех провайдеров
независимо от временного курсора: Kie передаётся UUID, Codex/RouterAI —
`codex:<UUID>`/`routerai:<UUID>`. Сервер разрешает ID только в выбранном аккаунте.
Это восстанавливает переходы, чья транзакция завершилась после снимка, но
`updated_at` оказался до курсора. Завершённое состояние также возвращается,
пока браузер считает задачу активной. Проверка: `test/generation-history.test.js`.

Проверки: `test/generation-history-page.test.js` покрывает три namespace,
активные задачи, 117 записей, курсор и изоляцию аккаунтов; нагрузочный сценарий
`tools/load-test/history.cjs` прошёл 10 000 записей и 200 страниц без пропусков
и повторов. Реализация: `src/services/generation-history.js`,
`src/server/http.js`, `web/src/stores/studio.ts`.
