# GI: исследование бизнес-логики

## Цель и результат

Пользователь попросил установить GI, изучить проект и сохранить бизнес-логику
и алгоритмы. GI установлен локально, существующее правило единственного
дистрибутива сохранено. Корень проекта относительный, определяется AGENTS.md.

Основная карта: [память проекта](../project-memory/README.md). Контракты описывают
существующую реализацию и не являются разрешением менять продукт.

## Главное для продолжения

- Не повторять неоднозначный POST генерации; различать паузу отправок и опрос.
- Очередь 1–5 задач, по умолчанию 3. Каталог 149 записей, это не live-проверка.
- Расходы, оценки и баланс имеют разный смысл; неизвестное не равно нулю.
- Локальные файлы переживают перезапуск, для новой задачи загружаются заново.
- Черновик может быть невалидным для API; закрытие ожидает его сохранения.
- Риски поиска модели по API-имени, восстановления фильтров и IPC отражены
  в known-issues.md; исправления не выполнялись.

## Проверка и границы

Синтаксис main/preload/renderer и загрузка каталога проверены. Проверка
документационных ссылок, JSON, PowerShell-синтаксиса и diff выполнена отдельно.
Unit/UI-тесты и сборка продукта не запускались; внешние API и профиль пользователя
не читались. GI 2026.09.05.1, неприменённых миграций 0.

SQLite рекомендован размером дерева, но не включён; Markdown остаётся источником
истины. Выбор WorkNest/none предложен пользователю; синхронизация не подключена.
