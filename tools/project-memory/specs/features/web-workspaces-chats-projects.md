# Проекты и чаты веб-студии

## Границы данных

- Каждый проект и чат принадлежит одному media_accounts.id.
- Проект хранит имя, владельца, даты создания/изменения и archived_at.
- Чат хранит имя, необязательный проект, контекст JSON, даты и archived_at.
- При OAuth-регистрации в той же транзакции создаётся отдельный основной чат аккаунта. Полный снимок рабочего пространства создаёт такой чат для старых аккаунтов, у которых его ещё нет. Первый вход выбирает его, если браузер не хранит выбор другого чата.
- Каждая новая генерация, черновик и сохранённый исходник получают chatId: если клиент его не передал, сервер выбирает или создаёт основной чат аккаунта либо выбранного проекта. Проектный чат нельзя использовать с другим projectId. Архивирование основного чата аккаунта создаёт новый основной чат.
- При чтении черновика без chatId сервер сначала ищет его в основном чате; если такого черновика ещё нет, доступен прежний workspace-черновик. Следующее сохранение без chatId записывает данные в основной чат.
- Виртуальный системный раздел system:recent («Без чата») показывает только исторические генерации без chatId; он скрыт, когда таких записей нет. Новые генерации из него переводят пользователя в основной чат. Полная история всех чатов остаётся в разделе «История». Старые записи без chatId не мигрируют автоматически.

## Контракт операций

- GET/POST/PATCH /api/projects и POST /api/projects/:id/archive, /restore выполняются только в account scope.
- GET/POST/PATCH /api/chats, POST /api/chats/:id/move, /archive, /restore и DELETE /api/chats/:id выполняются только в account scope.
- Архивирование помечает проект/чат датой и не удаляет записи генераций, исходники или результаты.
- Архивные проекты и чаты доступны в отдельной вкладке панели. Восстановление проекта возвращает сам проект; ранее архивированные чаты восстанавливаются отдельно. Чат архивного проекта нельзя восстановить до проекта.
- Окончательно удалить можно только архивный чат. UI предупреждает о необратимом удалении чата, его черновика, истории генераций и принадлежащих ему файлов. Незавершённые и неопределённые задачи блокируют удаление. Удаление записей атомарно, их идентификаторы защищены от повторной записи; собственные файлы ставятся в устойчивую очередь очистки с повторами. Общие исходники, журнал генераций и платёжные записи сохраняются.
- Перед привязкой генерации проверяется существование и принадлежность проекта/чата аккаунту; архивные рабочие области не принимают новые генерации.
- Если указан только чат проекта, сервер восстанавливает projectId из чата. Несовпадение проекта и чата отклоняется.
- Администратор может выбрать другой аккаунт только через существующий account-scope механизм; пользователь не может подменить tenant.

## Рабочий процесс UI

- Под готовым медиа-результатом в ленте чата показывается заметная кнопка «Скачать». Она не открывает боковую панель; для записей без медиа кнопка не показывается.
- Скачивание результата Kie всегда идёт через авторизованный `/api/results/:id/:index?download=1`: сервер при необходимости сохраняет файл из URL провайдера и отдаёт его как вложение. Внешний URL используется только для предпросмотра до появления локальной копии.
- Нажатие на изображение результата в чате, правой панели или истории открывает полноэкранный просмотр с кнопкой скачивания исходного файла. Просмотр закрывается клавишей Esc, кнопкой закрытия или нажатием на фон; фокус возвращается к миниатюре.
- При первом входе документ показывает полноэкранный брендированный экран запуска: центр логотипа совпадает с центром фоновых колец, по внутреннему кольцу непрерывно движется светящийся прогресс-сегмент, фоновые кольца пульсируют с разной фазой, а логотип и индикатор слегка «дышат». Переключатель анимации на splash не показывается. Без сохранённой настройки анимация всегда включена по умолчанию, независимо от `prefers-reduced-motion`; режим можно изменить отдельной кнопкой hero публичной главной, выбор сохраняется в браузере и применяется до появления разметки splash. Тот же режим управляет hero-композицией публичной главной: полноэкранный приглушённый видеоряд показывает работу с футуристическим визуальным интерфейсом, оставляет затемнённую область слева под текст и при выключении режима действительно приостанавливается. Исходник — [Mixkit 51214](https://mixkit.co/free-stock-video/a-woman-wearign-a-futuristic-vr-glasses-concentrates-on-the-51214/) по [Mixkit Stock Video Free License](https://mixkit.co/license/#videoFree), поэтому двоичный ролик не хранится в Git, а загружается с CDN владельца вместе с poster-кадром. Горизонтальная лента «Модели в одном интерфейсе» является бесшовной медленной каруселью: каждая модель показана вместе с логотипом, а дублированный скрытый от accessibility набор обеспечивает непрерывный цикл без скачка. При выключенной анимации карусель остаётся на месте. Публичная главная открывается после минимальной бренд-паузы 2,2 секунды для любого посетителя и никогда не перенаправляет авторизованную сессию автоматически; студия открывается только по явной ссылке на `/app`.
- Якорные контролы публичной главной перемещают viewport отменяемым покадровым lerp без скачка. Повторное нажатие меняет цель с текущей позиции, а колесо, касание и клавиши прокрутки немедленно возвращают управление пользователю. Системный reduced-motion сохраняет мгновенный переход, если пользователь явно не включил анимацию.
- После прокрутки первого экрана главная показывает фиксированную круглую стрелку «наверх». Она доступна для клавиатуры, возвращает к началу тем же lerp и снова скрывается у верхней границы страницы.
- Первоначальная загрузка аккаунта выполняется одним `GET /api/workspace/sync` без курсора и возвращает согласованный курсор, историю, проекты, чаты и состояние очереди. После готовности интерфейс не блокируется повторно из-за переходов между разделами.
- Левая панель имеет ссылку «Главная» на публичный лендинг `/`, внутреннюю кнопку «Обзор» на `/app/home`, отдельный раздел «История», вкладки «Чаты» и «Проекты», поиск и сворачивание. Главная и студия находятся в одной SPA-оболочке: переходы «Главная» / «Обзор» / «Генерация» / «История» меняют URL через History API, сохраняют смонтированную студию и все Pinia-данные, не показывают startup повторно и не запрашивают новый полный snapshot. «История» показывает все завершённые генерации аккаунта; выбор записи оставляет список слева и открывает справа read-only форму с промптом, ответом/медиа и параметрами, а возврат в генерацию сохраняет текущий чат и черновик.
- Чаты группируются по дате; «Ранее» обозначает группу старых чатов, а «Без чата» — только записи без привязки к чату. Счётчик системного раздела отражает только эти записи. Переключение вкладок «Чаты»/«Проекты» и раскрытие проекта меняют только навигацию левой панели и сохраняют текущий чат; новый активный чат выбирается только явным нажатием на конкретный чат.
- Для чата и проекта доступны переименование, перенос чата и архивирование через контекстное меню. Вкладка «Архив» показывает архивные проекты и чаты, позволяет восстановить их и предлагает «Удалить навсегда» только для чатов с обязательным предупреждением.
- Выбранный чат становится единым контекстом composer, очереди, результата и истории.

## Composer и результаты

- Composer закреплён внизу центральной области и переключается между текстом, изображением, видео и аудио.
- Лента каждого чата хранит собственную позицию прокрутки в локальном состоянии браузера. При первом открытии без сохранённой позиции показывается последнее сообщение; при возврате в чат восстанавливается прежнее место. Если пользователь ушёл вверх, над composer появляется круглая кнопка со стрелкой вниз, которая плавно переводит к последнему сообщению; новые результаты удерживают низ только когда пользователь уже находился внизу.
- Для Codex доступны модель, уровень рассуждений, скорость и формат изображения; для Kie поля строятся из каталога модели, включая исходники и дополнительные параметры.
- Один клик по запуску composer создаёт ровно одну задачу; отдельного выбора количества и скрытого пакетного запуска нет. Кнопка показывает стоимость этой задачи до отправки и остаётся доступной во время уже запущенных запросов: каждый повторный клик немедленно добавляет отдельную предварительную карточку в очередь и сопровождается анимацией перелёта к очереди.
- Новая задача автоматически становится выбранной в панели результата. Нажатие на любую карточку изображения, видео, аудио или текста в очереди переключает панель на актуальные этапы именно этой задачи; ответы предыдущих параллельных запусков не должны перехватывать выбор у более нового запуска.
- Черновик промпта, режим, модель, параметры и исходники сохраняются отдельно для каждого чата.
- Правая панель разделяет очередь выбранного чата и подробности выбранного результата; активность других чатов показывается отдельным индикатором. Список завершённых результатов находится только на отдельном экране «История» и не дублируется в правой карточке.
- У каждого Kie-item очереди есть удаление. Только локальные `queued`/`preparing` удаляются сразу; для уже отправленных или неопределённых показывается предупреждение о возможном списании токенов Kie и продолжении удалённой генерации. «Очистить всё» применяет ту же политику ко всем Kie-item аккаунта, включая другие чаты, и не затрагивает завершённую историю; после удаления клиент запрашивает полный снимок, а SSE reset удаляет записи из памяти остальных открытых вкладок.
- Результат показывает медиа, модель, время, стоимость и токены; повтор и редактирование сначала возвращают параметры в composer и не запускают платную операцию автоматически.

## Адаптивность

- На широком экране одновременно видны левая панель, рабочая область и правая панель.
- На среднем экране правая панель открывается поверх рабочей области.
- На телефоне чаты, рабочая область и результаты представлены отдельными экранами с нижней навигацией; composer остаётся доступным без вложенной прокрутки.
- Последний активный чат и проект восстанавливаются из локального состояния браузера, а серверный черновик восстанавливает содержимое composer.
- Лента чата резервирует высоту для каждого изображения и видео до получения медиа-данных. Загрузка файлов после входа или обновления страницы не меняет высоту карточек и не перенаправляет прокрутку. Для каждого чата браузер сохраняет видимую запись и смещение внутри неё, восстанавливает именно это место после обновления страницы и не перезаписывает сохранённую позицию, пока студия скрыта или ещё загружается. При уходе со страницы текущая позиция записывается немедленно.
- Нижний индикатор соединения после готовности студии фиксирует три длительности текущего запуска страницы: от начала инициализации до доступности БД, загрузку данных аккаунта и общее время до разблокировки рабочего пространства. Значения не продолжают увеличиваться после готовности.

## Инкрементальная синхронизация

- После первоначального снимка клиент хранит серверный курсор и запрашивает `GET /api/workspace/sync?since=<cursor>` при серверном событии изменения или для уточнения состояния активной генерации. В запросе он также передаёт до 20 ID активных Kie-задач через повторяющийся параметр `active`.
- Delta-ответ содержит записи, изменённые в интервале `(since, cursor]`, и актуальные записи запрошенных активных задач независимо от курсора. Проекты и чаты ограничены тем же интервалом; архивные сущности передаются как tombstone через `archivedAt` и удаляются клиентом из активного представления.
- Стартовое SSE-сообщение `ready` не вызывает дополнительный запрос после первоначального snapshot. События `changed` и повторный `ready` после переподключения запрашивают только cursor-bounded delta; повторные события во время выполняющейся синхронизации объединяются в один следующий delta-запрос.
- Локальные CRUD-операции над проектами и чатами применяют возвращённую сервером сущность напрямую. Счётчики материалов и чатов пересчитываются из уже загруженного состояния, без перечитывания всего рабочего пространства.

## Проверки

- API-тесты проверяют tenant isolation, создание, переименование, перенос, архивирование, chat-scoped draft, сохранение projectId/chatId у генераций, полный bootstrap и ограниченную курсором delta-синхронизацию.
- UI smoke проверяет загрузку Vue SPA, восстановление чата и черновика, сохранение активного чата и позиции его ленты при навигации, переход к последнему сообщению, единственный полный bootstrap, переход на внутреннюю главную без новых workspace-запросов, четыре режима composer, стоимость и телефонную навигацию.
- При выпуске обязательны Vue type-check, серверные тесты, сборка, Docker health и визуальная проверка широкого, среднего и телефонного состояния.
