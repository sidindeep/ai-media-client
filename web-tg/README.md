# AI Media Web + Telegram

Самостоятельный переносимый модуль веб-интерфейса и Telegram-бота. Windows-приложение находится вне этой папки и не требуется для запуска.

## Запуск

Нужны Node.js 22.9+ и pnpm. Выполняйте команды из этой папки:

```powershell
pnpm install --ignore-workspace --frozen-lockfile
pnpm start
```

Открыть http://127.0.0.1:3000. Остановить — Ctrl+C. Разработка: `pnpm dev`.
Проверки: `pnpm check` и `pnpm test`.

## Модули

- `public/` — страница, HTTP-мост и стили веба.
- `src/server/` — конфигурация, HTTP API, статика и события SSE.
- `src/services/` — прикладной сервис генерации, контролы бота и Telegram transport.
- `src/providers/kie/` — клиент протокола Kie.
- `src/media/` — прикладной контракт медиа и адаптер; не часть библиотеки провайдера.
- Остальные `src/` — собственная копия каталога, очереди, хранения, расчётов и браузерных компонентов прототипа. Они больше не читаются из Windows-проекта и развиваются независимо.
- `test/` — проверки сервиса, бота и границ модуля.
- `data/service/` — локальные данные сервиса, исключены из Git.

## Перенос

Скопируйте всю папку `web-tg` в нужный каталог, кроме `node_modules`, `artifacts` и логов. Установите зависимости командой выше. Абсолютных привязок к исходному проекту и зависимости от Electron нет.

Перед переносом существующих данных остановите сервис. Для сохранения истории, исходников и черновиков перенесите также `data/service/`. Для чистой установки этот каталог не нужен. Секретный `.env` настраивается отдельно на сервере; образец — `.env.example`. Не включайте его в публичные архивы или Git.

Без ключа Kie доступны интерфейс и черновики; генерация выключена. Telegram запускается только после настройки токена и списка операторов. [Настройки и команды бота](docs/web-and-telegram.md).

## Docker

Из этой папки: `docker compose build`, затем `docker compose up -d`.
Перед запуском контейнера остановите локальный Node-сервис: порт и данные у них общие, одновременно запускать их нельзя. Нужен локальный `.env` (можно скопировать `.env.example`). Секреты и данные не входят в образ; данные подключены из `data/service/`.

Проверить: `docker compose ps` и http://127.0.0.1:3000/api/health.
Штатная остановка: `docker compose down` — данные сохраняются.
После изменения `.env`: `docker compose up -d --force-recreate`.
После аварийной остановки проверяйте отсутствие прежнего процесса/контейнера перед удалением `data/service/service.lock`, как при обычном запуске.

Журнал всей цепочки: [generation-logging](docs/generation-logging.md).
