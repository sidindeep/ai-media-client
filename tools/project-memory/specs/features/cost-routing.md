# Автоматический выбор провайдера

Статус на 2026-09-29: административный пилот для GPT Image 2 Text to Image.
Дальнейшие этапы: [план](../../../../docs/cost-routing-plan.md).

## Граница и владение

`src/services/cost-router.js` владеет выбором предложения, сравнением закупочных
цен и неизменным решением по `requestId`. Подтверждённые соответствия моделей
и учётная закупочная цена Kie находятся в `config/cost-routing.json`.
Адаптеры Kie и APIMart владеют собственными каталогами, ценами и отправкой.
Существующие обработчики генераций владеют очередью, опросом, результатом
и расчётом с провайдером. Кошелёк приложения остаётся в `src/billing/`.

Решение хранится в `media_records` с namespace `auto-route`; оно содержит
выбранное предложение, остальные котировки, причину недоступности и digest
запроса. Данные не входят в пользовательскую историю и выдаются только
административному маршруту `/api/auto/quote`. `/api/auto/jobs` использует
сохранённого провайдера при повторе того же `requestId`, даже если цены
изменились. Другой запрос с тем же ID отклоняется.

## Пилотный поток

Администратор выбирает Kie GPT Image 2 Text to Image, текст, соотношение сторон,
разрешение 1K и непрозрачный фон, включает автовыбор. Исходные изображения
и несовместимые опции исключены.
Backend получает закупочную цену Kie через тот же поиск источников, что и
пользовательская котировка, и переводит кредиты Kie по опубликованной
учётной закупочной цене в USD. APIMart возвращает `amountUsd` для `size`,
`resolution`, `n=1`. Оба маршрута проверяют доступный баланс. Маршрут
с неизвестной ценой или недостаточным балансом не участвует в сравнении.
Меньшая цена выбирается первой; равенство разрешается порядком из конфига.

После сохранения решения вызывается существующий `createTask` Kie или
`apimart.submit`. Оба маршрута резервируют кредиты приложения по собственной
котировке; APIMart после подтверждённого результата уточняет списание по
фактическому расходу. Интерфейс администратора показывает провайдера,
цену для пользователя в кредитах сервиса и ориентировочную закупочную цену
в USD. Неопределённый платный POST
не переключается на другого провайдера.

## Ограничения и проверка

`0.005 USD/кредит Kie` — версионированная учётная закупочная цена из
официальной публичной информации, которую владелец должен обновлять при
изменении фактической закупочной цены. Котировки APIMart являются оценкой,
поэтому победитель определяется по доступной предварительной цене.
Таблица сравнения показывает отдельные величины: цену для пользователя в
кредитах сервиса, количество кредитов провайдера, цену одного кредита
провайдера в USD и общую закупочную оценку в USD. Для Kie количество кредитов
равно `amountUnits / 1000`, а цена одного кредита берётся из
`config/cost-routing.json`. Для APIMart используются `nativeCredits` и
отношение `amountUsd / nativeCredits` одной котировки. Только продуктовые
кредиты из колонки «Цена для вас» резервируются и списываются с баланса.
Если для модели APIMart нет подтверждённой пары Kie, строка Kie показывает
прочерки вместо модели и цен с причиной исключения. Котировка APIMart может
быть выбрана самостоятельно. Таблицей соответствий владеет PostgreSQL-таблица
`media_service_model_configs`: каждая запись хранит версию и строки с APIMart ID,
тарифами APIMart, Kie ID, тарифами Kie и именем нашего сервиса. Частичный уникальный индекс разрешает
не более одной текущей записи. При первом запуске начальная запись создаётся
из `config/service-models.json` только если текущей ещё нет; повторный запуск
не заменяет выбранную версию. Смена текущей записи выполняется транзакционно
через `activateModelConfig`. Авторизованный web-клиент получает текущую запись
через `GET /api/service-model-config/current` и показывает имена из её колонки
`name`. Снимок исходной таблицы остаётся в `docs/model-correspondence.md`, а
Excel-выгрузка хранится отдельно от исходников. Для каждого действия Kie
сохраняется отдельная строка. В объединённом выборе совпавшая модель APIMart не даёт
второй пункт; прямой выбор APIMart остаётся в ручном режиме. Таблица имён
не подтверждает перенос параметров и не расширяет маршруты — их владелец
`config/cost-routing-compatibility.json`. Снимок выбранных строк находится в
`docs/model-correspondence.md`; новые ID и тарифы попадают в меню после обновления
таблицы соответствий.
Отдельные строки по действиям — временный выбор пользователя от 2026-09-29.
После тестирования удобства выбора и работы вариантов пользователь может
вернуться к варианту одной строки на версию модели; до такого решения
сохранять текущие отдельные строки.
Полный снимок опубликованных Kie API model paths находится в
`config/kie-market-models.json`; он включает модели, которые ещё не подключены к
генерации в приложении. Полный набор кандидатов с последним снимком цен хранится в
`config/service-model-candidates.json`. Генератор объединяет его с локальным каталогом
Kie и снимком APIMart. Каждая строка хранит ID и доступные тарифы каждого
провайдера отдельно; отсутствие тарифа обозначается пустой строкой или «—».
«Наш сервис 1» содержит только строки с хотя бы одной доступной ценой.
«Наш сервис 2» содержит строки «Наш сервис 1», где заполнены оба ID; достаточно
цены хотя бы одного провайдера. Наличие цены в снимке не гарантирует работающий
API-адаптер, актуальную котировку или совместимость параметров.
Команда `node scripts/sync-service-models.cjs <снимок APIMart> --no-markdown`
обновляет конфигурацию без изменения Markdown, затем
`node scripts/import-service-model-config.cjs` импортирует новую версию и
активирует её в БД. Смена имени в БД не добавляет отсутствующий API-адаптер.
`config/service-models-v2.json` — производная версия «Наш сервис 2»: строки
«Наш сервис 1», где заполнены оба ID. Её `baseVersion` равен версии полной
таблицы; генератор обновляет обе конфигурации вместе. БД хранит вариант, имя и
исходную версию каждой записи, сохраняя ровно одну глобально текущую. Импорт
V2 с `--inactive` не меняет текущую запись. В UI пока показан только список
«Наш сервис 2», а V1 сохранён в БД для возможного возврата. При первом запуске
V2 становится текущей версией. В существующей БД её активируют отдельно.
В V2 список Kie/APIMart строго ограничен общими строками с доступной ценой;
название списка показано на кнопке выбора модели. Если текущая запись БД — V1,
клиент загружает V2 по ID, не изменяя глобальную текущую запись.
Все провайдеры изолированы, включая получение контекста аккаунта и баланса.
Отказ всех маршрутов возвращает `selected:null` с причинами и известными ценами;
submit запрещён до записи решения и платного вызова. UI показывает эти строки.
Перенос content-ref выполняет общий mapper по схеме назначения и таблице
соответствий; потеря исходников запрещена. Layer Decomposition использует
константу режима из пары и тариф резерва APIMart, а не цену обычной генерации.
Собственный тариф и доступность провайдера не зависят от наличия другого.

Проверки: `test/cost-router.test.js`, профильные тесты Kie/APIMart,
контейнерная проверка и web/API health после пересборки Compose.

Аудит каталога: `scripts/audit-provider-quotes.cjs`, без генераций, отчёт в `data/service/diagnostics/`.
