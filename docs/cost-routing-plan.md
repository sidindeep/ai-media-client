# Автоматический выбор провайдера по себестоимости

Статус: административный пилот и объединённый каталог Kie/APIMart реализованы
2026-09-29; проверка новых соответствий, наблюдение в эксплуатации и этап 2 ещё впереди. Основа — действующие маршруты генерации Kie, RouterAI,
APIMart и Codex. Новые провайдеры подключаются в текущем проекте.

## Цель и порядок

Пользователь задаёт модель, параметры и исходники. Перед действующим блоком
«Выбранный провайдер» backend находит совместимые предложения, рассчитывает
полную закупочную стоимость в USD и выбирает минимальную. Дальше используются
существующие обработчики отправки, очереди, опроса, сохранения и учёта.
После отладки выбора действующий модуль биллинга будет рассчитывать и показывать
пользователю цену выбранного предложения в кредитах приложения.

## Этап 1 — выбор и проверка

1. Ввести каталог явно подтверждённых соответствий модели и параметров у
   провайдеров. Похожее имя не является доказательством эквивалентности.
2. Для каждого совместимого маршрута получить полную котировку без платного
   запроса. Неизвестная цена, неподдерживаемая опция и устаревший закупочный
   курс исключают предложение; нулевая цена требует явного подтверждения.
3. Привести сумму к USD с сохранением исходной единицы, версии тарифа,
   закупочной цены/курса и времени котировки. Различать точную цену, оценку
   переменного расхода и ограниченную сверху сумму. Не округлять до центов
   перед сравнением.
4. Выбрать минимум среди совместимых предложений. При равенстве использовать
   явный стабильный приоритет. Сохранить решение и причины исключения.
5. Проверить цену перед платной отправкой. После начала отправки закрепить
   маршрут: неизвестный исход POST нельзя автоматически повторять у другого
   поставщика. Подтверждённый отказ до принятия задачи допускает новое решение.
6. Для всего объединённого каталога проверять оба роутера. Соответствия
   моделей фиксировать в `config/cost-routing-compatibility.json`; отсутствие
   записи явно показывать как недоступный второй маршрут. Не отправлять
   неподдерживаемые параметры к другому провайдеру.

Пример соответствия: Kie `gpt-image-2-text-to-image` и APIMart `gpt-image-2`,
генерация одного изображения по тексту без исходников. Общими параметрами
являются `prompt`, поддерживаемые обоими соотношения сторон и разрешение 1K.
Прозрачность отключена (`background=opaque`); APIMart получает
`size`, `resolution`, `n=1`. APIMart пока доступен только администратору;
его задачи резервируют и списывают кредиты сервиса в соотношении 1:1.
Автомат использует только основной аккаунт `Kie.ai · 1` (`primary`);
`Kie.ai · Sid` (`secondary`) остаётся самостоятельным ручным выбором в меню.
Для Nano Banana Pro таблица связывает Kie `nano-banana-pro` и APIMart
`gemini-3-pro-image-preview`. Общие текстовые настройки без исходников
переводятся в `size`, `resolution`, `n=1`; APIMart возвращает базовую цену для
1K/2K и отдельную для 4K. Источники параметров: [Kie](https://docs.kie.ai/market/google/pro-image-to-image),
[APIMart](https://docs.apimart.ai/en/api-reference/images/gemini-3-pro/generation).

В web-студии администратор выбирает «Автомат» в меню поставщиков. Форма
объединяет каталоги `Kie.ai · 1` и APIMart по режимам через
[таблицу имён и моделей](model-correspondence.md). В выборе показан столбец
«Наш сервис»: отдельное действие Kie остаётся отдельной строкой, а общий ID
APIMart не создаёт повторный пункт. Модели без пары остаются в выборе.
В выборе модели сейчас показан только «Наш сервис 2»: модели, указанные и у Kie,
и у APIMart, с ценой хотя бы у одного из них. Список «Наш сервис 1» сохранён
в БД, но скрыт в интерфейсе. Название списка видно на кнопке выбора модели.
Цены и состав относятся к снимку из таблицы соответствий; текущая котировка
проверяется отдельно.
Таблица имён не включает неподтверждённые маршруты в сравнение цен;
совместимые пары из `config/cost-routing-compatibility.json` сравниваются по закупочной цене для
текущих параметров. Если модели нет у второго провайдера, поле обязательно
отсутствует или тариф неизвестен, второй маршрут виден с причиной исключения.
Совпадение названия само по себе не включает сравнение цен.
В новом чате администратора без сохранённого черновика «Автомат» выбран по
умолчанию, если доступен каталог для начального режима изображения. Сохранённый
ручной выбор в существующем чате восстанавливается без изменений.
После предварительной котировки форма показывает имя выбранного поставщика
и его закупочную оценку в USD под кнопкой генерации. На кнопке видна цена
выбранного маршрута в кредитах сервиса; для APIMart рядом указана оценка USD.
Кнопка «Детали» рядом с предварительным выбором открывает таблицу всех
маршрутов, проверенных для текущей модели и параметров: человеческое название
выбранной модели и её ID у каждого провайдера, выбранный маршрут,
цену для пользователя в кредитах сервиса, количество кредитов провайдера,
закупочную цену одного кредита провайдера и итоговую сумму в USD, а также
причину недоступности, если маршрут исключён. «Цена для вас» означает кредиты,
которые спишутся с баланса пользователя. Если подтверждён только один маршрут,
таблица содержит одну строку. При изменении параметров старая таблица закрывается
вместе с устаревшей котировкой.
Один тарифный кредит Kie или APIMart соответствует одному кредиту сервиса.
Выбор сохраняется в
черновике чата. При выборе обычного
поставщика форма возвращается к ручной маршрутизации. Предварительный победитель
может измениться при повторной проверке цены перед отправкой; фактический
поставщик виден в записи задачи. Оценка в USD не является пользовательской
ценой в кредитах приложения.

## Этап 2 — развитие пользовательской цены

Текущий временный тариф Kie/APIMart — 1:1 с кредитами провайдера. APIMart
перед отправкой резервирует оценку в кошельке сервиса, а после известного
исхода завершает расчёт по фактическому расходу, если он известен. Неизвестный
исход удерживает резерв до сверки. В будущем здесь можно заменить соотношение
1:1 общей продуктовой ценой. Закупочная стоимость, фактический расход и цена
пользователя остаются разными полями.

## Проверка

- На одинаковых параметрах выбирается меньшая полная цена в USD.
- Предложение с иной моделью/версией или неподдерживаемой опцией исключается.
- Ошибки и неизвестные тарифы не становятся бесплатными предложениями.
- Повтор `requestId`, рестарт и неопределённый POST не создают вторую
  генерацию или списание.
- Существующие ветки провайдеров сохраняют свои состояния и результаты.
- После правок: `docker compose up -d --build`, `docker compose ps`,
  `http://127.0.0.1:3000/api/health`, затем проверки в новых контейнерах.
