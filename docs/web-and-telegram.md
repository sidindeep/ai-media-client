# Веб-версия и Telegram

Веб-сервис находится в корне репозитория и построен по схеме Benz AI: Node HTTP-сервер,
браузерные HTML/CSS/JS, отдельные сервисы и клиент провайдера. Веб теперь использует
Google/VK OAuth, PostgreSQL и отдельные аккаунты с нативными кредитами.
[Настройка и контракт аккаунтов](accounts-and-credits.md).
В auth-режиме Telegram доступен после привязки личного аккаунта из веб-сессии.
Платные задачи бота работают в пространстве связанного аккаунта и используют его
кошелёк. Локальный owner-only режим без авторизации по-прежнему использует старую
общую очередь.

## Запуск

Node.js 22.9+ (проверено на 24.14.1), зависимости из собственного pnpm-lock.yaml. Команды выполняются из корня репозитория.

```powershell
pnpm install --ignore-workspace --frozen-lockfile
pnpm start
```

По умолчанию: http://127.0.0.1:3000. Сервис остаётся работающим после закрытия
браузера. Остановка из терминала — Ctrl+C. `pnpm dev` включает watch.
Данные хранятся в `data/service/`, отдельно от профиля Windows-приложения.
История desktop автоматически не импортируется. Запуск двух процессов с одним
хранилищем блокируется файлом `service.lock`. После аварии удалять его можно
только убедившись, что предыдущий процесс завершён.

В `.env.example` перечислены настройки. Скопируйте его в `.env` при настройке:

- `MEDIA_HOST` / `MEDIA_PORT`: интерфейс и порт, по умолчанию loopback:3000.
- `MEDIA_DATA_DIR`: каталог данных внутри проекта, по умолчанию data/service.
- `KIE_API_KEY`: ключ сервисного аккаунта. В интерфейсе его нет; исходники и
  клиентские JS его не содержат. При пустом ключе каталог и черновики доступны,
  а генерация явно отключена.
- `KIE_API_KEY_2`: ключ второго аккаунта Kie. В меню поставщика администратора
  доступны «Kie.ai · 1» и «Kie.ai · Sid», каждый со своей проверкой подключения.
  Выбор сохраняется в черновике чата и применяется к новым задачам этого чата;
  уже принятые задачи продолжают использовать свой аккаунт после переключения
  и перезапуска. Обычные пользователи используют первый аккаунт. Ключи задаются
  только на сервере; после изменения `.env` выполните `docker compose up -d --build`.
  Не заменяйте ключ слота ключом другого аккаунта, пока у него есть незавершённые
  задачи: старые задачи принадлежат исходному аккаунту.
- `MEDIA_UPLOAD_LIMIT_MB`: максимальный исходник веба, по умолчанию 64 MiB.
- `MEDIA_RUB_PER_CREDIT`: исходная учётная цена кредита, по умолчанию 0.51.
- `MEDIA_PUBLIC_ORIGIN`: канонический HTTPS origin для reverse proxy и OAuth
  callback. Без авторизации публичный режим запрещён.

## Веб-контролы

- Выбор/поиск модели, фильтры изображений, видео и аудио, избранное.
- Общие с desktop динамические формы, включая вложенные параметры и файлы.
- Рабочие вкладки, автоматические черновики, библиотека промптов.
- Запуск, пауза, продолжение и очистка очереди, лимит 1–5.
- Предпросмотр, история, повтор с редактированием, расходы и справочные тарифы.
- Автосохранение результатов на сервере и скачивание из истории в браузер.
- Состояние подключения генерации и Telegram. Форм ввода ключа и входа Kie нет.

События очереди передаются через SSE, после переподключения история обновляется.
Черновик сохраняется после изменений и при уходе вкладки в фон. Неотправленный
JSON-снимок временно хранится в localStorage и восстанавливается в том же
браузере. До окончания сохранения браузер предупреждает о закрытии. Аварийное
закрытие во время чтения ещё не сохранённого файла не гарантирует его сохранение.
Браузер может ограничить несколько автоматических скачиваний; каждый уже
сохранённый результат также доступен отдельной кнопкой в истории.

## Telegram

Настройки сервера:

```dotenv
TELEGRAM_ENABLED=true
TELEGRAM_PUBLIC_ACCESS=true
TELEGRAM_BOT_TOKEN=
TELEGRAM_ALLOWED_USER_IDS=123456789
```

Для запуска нужны TELEGRAM_ENABLED=true и TELEGRAM_BOT_TOKEN. TELEGRAM_ALLOWED_USER_IDS
необязателен; TELEGRAM_PUBLIC_ACCESS=true открывает личные чаты всем, а false
ограничивает доступ перечисленными ID. Используется long polling; для одного
токена нужен один процесс и отсутствие активного webhook. После изменения
настроек пересоздайте контейнер. Состояние без токенов: `GET /api/health`.

В auth-режиме пользователь входит на сайт через Google/VK, открывает меню аккаунта
→ Telegram → «Создать ссылку привязки» и запускает бота по одноразовой ссылке.
Ссылка действует 10 минут, а Telegram ID можно связать только с одним аккаунтом;
у аккаунта одновременно может быть одна Telegram-привязка. Привязку можно снять
в том же меню. Telegram подтверждает пользователя через входящее личное сообщение
Bot API; отдельная Telegram OAuth-регистрация не используется.

Бот принимает генерации только после привязки. Он использует каталог и очередь
аккаунта, оценивает цену до подтверждения, а сервер повторно проверяет тариф и
баланс при постановке задачи. Запрос, резерв, списание и история принадлежат
аккаунту сайта. Стартовый GPT-доступ не открывает Kie-медиа из Telegram.

Бот принимает только личные чаты. В auth-режиме контент, история, очередь и
отмена задач ограничены аккаунтом, привязанным к Telegram ID. В локальном режиме
owner-only остаётся общая рабочая область.

- `/start`, `/help`, `/menu`: меню и команды.
- `/models название`: поиск, кнопки выбора, страницы по 8 моделей.
- Обычный текст: промпт черновика; сам по себе не запускает генерацию.
- Фото, видео или медиа-документ: исходник; подпись может задавать промпт.
- «Параметры»: выбор значений и поля для следующего файла.
- `/set поле значение`: параметр, включая JSON-объекты и массивы.
- `/params JSON`: замена входных параметров для сложной схемы.
- `/clear`: убрать исходники; `/new`: новый черновик выбранной модели.
- `/generate` или «Подготовить запуск»: проверка и отдельное подтверждение
  платной генерации. Повторное нажатие того же подтверждения не создаёт дубликат.
- `/queue`: состояние, пауза/продолжение, отмена ожидающих задач.
- `/history`: последние задачи и ссылки на результаты.

О завершении бот присылает сообщение со ссылками на медиа. Для сложных
вложенных наборов исходников используйте веб или /params; автоматическое
вкладывание Telegram-фото в произвольную вложенную схему не реализовано.
Файлы Telegram ограничены 20 MiB или меньшим лимитом модели.

## Архитектура и границы проверки

`src/services/media-service.js` — общая прикладная очередь/история/исходники.
`src/services/kie-generation.js` — адаптация каталога приложения к Kie.
Market-клиент из llm_providers скопирован в `src/providers/kie/` с manifest
происхождения; машинной зависимости от соседнего каталога нет. Он сохраняет
родные интерфейсы Kie. Специальные API используют существующие преобразования
`src/adapters.js` прототипа без изменения их протокольного контракта.
Каталог Kie содержит 176 моделей: 59 изображений, 90 видео и 27 аудио. Аудио-
раздел импортируется из `Music Models` официальной документации Kie и включает
ElevenLabs, Gemini TTS и Suno. Для аудиомоделей форма поддерживает текст,
параметры, загрузку аудиофайлов, расчёт тарифов «за запрос» и «за 1000 знаков».
Отдельная новая универсальная схема `src/media/` остаётся основой для будущего
переноса каталога; не все модели ещё описаны её семантическими профилями.

Веб-представление — `public/` плюс общие браузерные модули `src/`. Публичная
главная `/` — рекламный лендинг, рабочая Vue-студия открывается по `/app`;
анонимный переход в студию направляет на `/login`, успешный OAuth-вход — обратно
в `/app`. Legacy-интерфейс остаётся на `/legacy`.
Юридические страницы `/legal/terms`, `/legal/privacy`,
`/legal/personal-data-consent` и `/legal/offer` публичны и доступны независимо от
сессии и состояния БД. Пока реквизиты Оператора, трансграничная обработка и схема
оплаты не утверждены, они явно помечены как рабочие черновики.
Telegram — `telegram-bot.js` (сценарии) и `telegram-gateway.js` (Bot API).
Секреты, каталоги файлов и провайдерские URL не принимаются от браузера как
настройки. HTTP разрешает только явный список статики и RPC, проверяет origin,
Host и маркер same-origin запросов. Ключи и cookie Kie отсутствуют в API.
Локальный Compose запускает отдельный Chromium для входа в кабинет Kie.
Администратор открывает вкладку «Вход в Kie» на `/admin.html`, переходит в
браузер Docker по локальной ссылке и входит через Google или Microsoft.
Профиль браузера хранится в томе `ai-media-kie-session` между пересборками;
порт окна входа опубликован только на `127.0.0.1:5808`. Браузер запускается
без расширений, чтобы сторонние кошельки не вмешивались в страницу входа Kie.
Административный `GET /api/admin/kie-session/status` возвращает лишь состояние входа и локальную
ссылку, не возвращает токен или cookie. При запуске одиночного Docker-образа
внутри него автоматически запускаются Chromium и виртуальный экран. Во вкладке
«Вход в Kie» администратор открывает серверный браузер, нажимает на изображение
страницы и вводит текст с клавиатуры либо через поле ввода. Экран и действия
передаются только через администраторские API; CDP-порт наружу не публикуется.
Профиль одиночного образа сохраняется в `/app/data/kie-browser`, поэтому хостинг
должен сохранять `/app/data` между деплоями. Для внешнего входа нужен HTTPS.
Compose явно отключает встроенный браузер и использует отдельный контейнер.
Текущий расчёт генераций по-прежнему использует публичные тарифы Kie;
наличие сессии само по себе не переключает источник цены.

Проверки: `pnpm check`, `pnpm check:web`, `pnpm test`,
`pnpm exec electron test/ui-smoke.cjs` для сохранения desktop-поведения.
HTTP/бот тестируются подставными транспортами; реальная генерация зависит от
доступности настроенного Kie и баланса аккаунта.
Браузерная визуальная проверка выполняется пользователем по правилам проекта.

Переходы по внешним ссылкам разрешены для GET/HEAD публичной главной и страниц
приложения (Sec-Fetch-Mode: navigate, Sec-Fetch-Dest: document). Проверки Host и
источника запросов API сохраняются; внешние iframe не разрешены.

Публичный Telegram: любой личный чат может начать привязку; работа с данными и
задачами доступна после успешной привязки к аккаунту. Чужие аккаунты и их задачи
не доступны. Групповые чаты не поддерживаются.

Режим доступа переключается через TELEGRAM_PUBLIC_ACCESS: true (по умолчанию) —
личные чаты могут привязаться; false — обрабатывать можно только Telegram ID из
TELEGRAM_ALLOWED_USER_IDS. В закрытом режиме пустой список запрещает доступ всем,
включая привязку и уведомления. Аккаунты создаются входом Google/VK; отдельная
регистрация или вход через Telegram не реализованы. После изменения переменных
пересоздайте контейнер: `docker compose up -d --force-recreate`.
