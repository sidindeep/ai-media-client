# Структура базы данных

Снимок схемы v9 без пользовательских данных:

- [PostgreSQL](postgresql.sql) — точная копия исполняемого `src/database/schema.sql`. Это единственная СУБД, которую сейчас поддерживает приложение.
- [MySQL](mysql.sql) — соответствующая структура таблиц, ключей, индексов и ограничений для ручного изучения в MySQL 8.0.16+. Приложение к MySQL не подключается: его драйвер и запросы рассчитаны на PostgreSQL.

## Развёртывание PostgreSQL

Создайте пустую базу, затем выполните из корня проекта:

```powershell
psql -X -v ON_ERROR_STOP=1 -d 'postgresql://user@host:5432/ai_media' -f docs/database/postgresql.sql
```

Для проверки структуры используйте `psql -d ... -c '\dt'` и `psql -d ... -c '\d media_records'`. Скрипт идемпотентен и совпадает с тем, который приложение выполняет при старте. Для повторного развёртывания на другой сервер переносите данные отдельно; здесь только DDL и записи версий схемы.

## Развёртывание MySQL

Создайте **пустую** базу с бинарным сопоставлением, чтобы ключи и уникальность сохраняли регистр символов, как в PostgreSQL:

```sql
CREATE DATABASE ai_media CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;
```

Импортируйте `docs/database/mysql.sql` в эту базу из клиента MySQL с остановкой при первой ошибке. В MySQL Workbench выберите базу `ai_media` и откройте файл через **File → Open SQL Script**; после выполнения проверьте `SHOW TABLES;` и `SHOW CREATE TABLE media_records;`. Для SQL-файла используется `SET time_zone = '+00:00'`; приложение, работающее с этими данными, должно придерживаться UTC.

MySQL-схема повторяет назначение PostgreSQL-таблиц, но типы не полностью совпадают: `uuid` представлен `CHAR(36)`, `jsonb` — `JSON`, `timestamptz` — `DATETIME(6)`, а PostgreSQL `text` в индексируемых ключах ограничен длиной `VARCHAR` (обычно 255 или 512 символов). Уникальность `media_records` по `requestId` реализована вычисляемым полем `history_request_id`; уникальность `payment_attempts` с ненулевым `provider_payment_id` достигается обычным уникальным индексом, поскольку MySQL допускает несколько `NULL`. Эти различия следует учитывать при сравнении структуры и данных.

MySQL-файл не реализует PostgreSQL `LISTEN/NOTIFY` и частичные индексы истории; он служит справочником таблиц, а не готовым backend приложения.

Первичным источником изменений остаётся [исполняемая схема PostgreSQL](../../src/database/schema.sql). Снимок PostgreSQL должен совпадать с ней дословно; при изменении общих таблиц и ограничений обновляйте также MySQL-справочник.
