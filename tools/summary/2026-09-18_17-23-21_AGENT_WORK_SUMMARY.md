## Topic Theses

- Каждая генерация — отдельный `codex exec --ephemeral`. Предыдущие запросы и изображения автоматически не передаются; это не продолжаемый чат.
- Общая авторизация сохраняется, но задачи, результаты и кредиты изолированы по аккаунтам приложения. Повтор того же requestId не создаёт второй запуск.
- PNG сохраняется в `MEDIA_DATA_DIR/codex-images/<account>/<request>.png`; временный оригинал Codex удаляется. Получение PNG проверяет владельца. Для хостинга нужен постоянный каталог данных.
- Ограничение одного активного запроса было нашим кодом, а не доказанным ограничением Codex. Не повторять прежнюю оценку 30–100 генераций/час как актуальный предел после 0.3.3.
- Ограничение веб-SSE в 20 подключений осталось; это предел канала обновлений, не жёсткий предел всех HTTP-пользователей. БД использует пул из 10 соединений. У Kie отдельная очередь на аккаунт, обычно 3 параллельных задачи, максимум 5.

## Code, Architecture, Or Business Logic Changes

- src/services/codex-worker.js: отдельный CLI-процесс на запрос, общий сигнал остановки всех процессов; после снятия ограничения отключено предупреждение о числе слушателей этого сигнала. Таймауты 180 секунд для текста и 300 для изображения сохранены, как и проверки доступа/размера/формата.
- src/services/codex-request.js: JSONL включён для текста и изображений. В изображениях включены image_generation, code_mode и code_mode_host; ненужные инструменты отключены. Окружение CLI не наследует секреты БД/OAuth/Kie.
- src/services/codex-usage.js: usage берётся только из события завершения, а не текста модели. Всего = input + output; кэш входит во вход, reasoning входит в выход и не складывается повторно. При отсутствии полей — null. Текст извлекается из item.completed/agent_message.
- src/services/codex-billing.js сохраняет usage с результатом в PostgreSQL. Ошибка изображения без PNG возвращает резерв, неизвестный исход сохраняет резерв и не запускает повтор автоматически.
- public/codex-models.js показывает токены рядом со списанием и сохраняет сведения в последнем результате для восстановления интерфейса.
- src/services/codex-login.js и admin UI: фиксированные команды login/status/device-auth; один процесс входа, ожидание до 10 минут, отмена; токены и сырой вывод наружу не выдаются. CODEX_HOME создаётся перед входом и при старте встроенного worker.
- src/server/build-info.js: версия из package.json, канал debug, автоматический хеш файлов приложения, дата Docker-сборки при совпадении манифеста. /api/version публичен и не зависит от БД после запуска HTTP; /api/health сообщает version/build. public/version.js выводит метку на всех трёх веб-страницах. HTTP запускается только после успешной инициализации БД.
- Основная инструкция эксплуатации и текущие правила: docs/codex.md. Локальный запуск: docker compose up -d --build.

## Known Failures Or Caveats

- Локальная БД периодически отвечает CONNECTION_TIMEOUT при старте. Последний запуск сам восстановился на повторных попытках. Не превращать это в основную задачу без нового запроса или фактической блокировки.
- При прерывании старта ранее оставался data/service/service.lock. Его удаляли только после подтверждения, что контейнер завершён и порт не прослушивается. Не удалять блокировку работающего сервиса.
- Встроенный браузер Codex блокировал localhost с ERR_BLOCKED_BY_CLIENT; UI проверяли скрытым Electron smoke на изолированной БД. На рабочем аккаунте UI автоматически не подтверждался через этот браузер.
- Хостинг: https://ai-media-client.bothost.tech/. Пользователь уже включил собственный Dockerfile. Пуш не доказывает пересборку Bothost; фактическую версию проверять в UI/API. На скриншоте пользователя 0.3.2 уже показывала токены.
- Реальные лимиты аккаунта Codex, характеристики хостинга и предел параллельной генерации не измерены. После снятия ограничения число процессов и объём временных PNG в памяти могут расти; сохранён часовой срок кеша, но нет численного лимита задач.
