# Web и Telegram: контракт первой версии

С 2026-09-18 актуальное многопользовательское поведение описано в
[accounts-credits.md](accounts-credits.md): OAuth, PostgreSQL, раздельная история,
роли и нативные кредиты. Описанный ниже общий workspace сохраняется только как
admin legacy/local режим. Telegram в auth-режиме доступен после account linking;
контракт привязки и списания описан в accounts-credits.md.

С 2026-09-21 публичные юридические страницы `/legal/terms`, `/legal/privacy`,
`/legal/personal-data-consent` и `/legal/offer` доступны без сессии и базы данных;
лендинг и вход ссылаются на них. Их статус, фактические основания и блокеры перед
коммерческой публикацией закреплены в
`../business-rules/legal-documents.md`.

2026-09-17 пользователь разрешил веб-версию по структуре Benz AI и Telegram-бота,
с контролами по усмотрению на основе desktop-прототипа. Ключи и вход Kie в UI
не требуются: общий API-ключ задаётся внутри серверного окружения.

## Состав

Node HTTP entrypoint server.js, config src/server/config.js, API/static/SSE
src/server/http.js. src/services/media-service.js владеет Assets, History,
PromptTemplates, TaskQueue и настройками. Провайдер передаётся зависимостью.
Kie-generation адаптирует текущие catalog/adapters; Market использует копию
нативного Kie-клиента из llm_providers, происхождение и SHA-256 в provenance.json.
Специальные API сохраняют существующие протоколы desktop; внешняя библиотека
не расширялась ими. src/media/ не является полным контрактом всех моделей пока.

Веб и разрешённые Telegram-операторы имеют одну очередь и историю. Это не
многопользовательский публичный сервис. Данные web отделены от Electron userData.
Сервер по умолчанию loopback:3000; отсутствие ключа не мешает просмотру форм и
сохранению черновиков, но запрещает создание задач. Нет implicit demo-результатов.

## Поведение

### Светлая и тёмная темы

- Все web-поверхности — публичный лендинг, вход, Vue-студия, legacy-студия, админка и юридические страницы — поддерживают две темы: `dark` и `light`. Тёмная сохраняет исходную кинематографичную палитру, светлая использует тёплый нейтральный фон, белые рабочие поверхности, фиолетовый акцент студии и оранжевый брендовый акцент.
- Выбор хранится локально под ключом `ai-media-studio-theme` и действует на всём origin без привязки к аккаунту. При отсутствии сохранённого выбора используется `prefers-color-scheme`; после ручного выбора системная тема не перезаписывает предпочтение.
- Тема устанавливается внешним скриптом в `<head>` до загрузки основных таблиц стилей, поэтому переходы между публичными и авторизованными страницами не должны показывать вспышку противоположной темы. Скрипт также синхронизирует `color-scheme`, `meta[name="theme-color"]`, доступное имя кнопки и изменения из другой вкладки.
- В Vue-студии переключатель остаётся в верхней панели рядом с уведомлениями и балансом. На остальных страницах доступна кнопка с тем же поведением в основной шапке или верхней строке карточки.

### Центральная лента результатов чата

- Центральная колонка Vue-студии показывает задачи текущего чата как хронологическую чат-ленту; форма генерации остаётся под лентой. Полное приветствие выбранной модели и подсказки промптов показываются только в новом пользовательском чате без материалов и задач. В системном разделе «Ранее» и после первой отправки подсказки скрываются; над заполненной лентой остаётся только компактная информация о выбранной модели.
- Каждый элемент ленты содержит промпт, модель, провайдера, состояние, превью результата или текст, дату, длительность, кредиты, токены и выбранные режимы рассуждения/скорости, когда эти данные доступны.
- Если сервер отклонил запрос до создания постоянной записи, optimistic-элемент становится локальной карточкой «Ошибка» с причиной и остаётся выбранным в центральной ленте до перезагрузки; он не остаётся активным в правой очереди и не попадает в серверную историю.
- Выбор элемента в центре меняет `selectedId`, поэтому существующая правая карточка показывает полную детализацию именно этого результата. На узких экранах выбор также открывает правую панель/мобильный раздел результатов.
- Правая очередь и подробная карточка результата сохраняются, но прежний встроенный список завершённых результатов из карточки перенесён в отдельный раздел «История». Пункт раздела находится в левой панели сразу под «Главная», показывает все завершённые генерации аккаунта без лимита первых 12 записей и прокручивается внутри рабочей области. Выбор записи синхронизирует её чат-контекст и открывает подробности справа; возврат «К генерации» не меняет выбранный чат или его черновик. Центральная лента по-прежнему фильтруется по `activeChatId`/`activeProjectId` и не меняет account-scoped изоляцию.
- Масштабирование формы под лентой временно отключено: на desktop она сохраняет фиксированную компоновку 1020 × 230 px (с уменьшением ширины по контейнеру), поле промпта имеет высоту 76 px и не растягивается вручную. На мобильном форма остаётся адаптивной по высоте.
- Переключение режимов «Текст / Изображение / Видео / Аудио» остаётся во вкладках над формой. Только в канале `debug` внизу левой колонки показывается отладочное меню поставщиков «Codex CLI / Kie.ai» с кнопкой проверки Kie.ai; поясняющий текст возле формы удалён. В release-канале этот блок отсутствует. Смена режима или поставщика продолжает нормализовывать модель, поля и исходники по прежним правилам.

### Аудиомодели Kie

- Импортёр читает раздел `Music Models` из `https://docs.kie.ai/llms.txt` с
  `Accept: text/markdown`; режим `--only-audio` обновляет аудиомодели, не удаляя
  сохранённые модели изображений и видео.
- Каталог содержит 27 аудиомоделей Kie: ElevenLabs, Gemini TTS и операции Suno.
  Они используют тот же единый `createTask`/`getTask`, очередь, историю,
  изоляцию аккаунтов и вывод `<audio>`, что и остальные Kie-задачи.
- Поля `audio_url`, `audio_urls`, `upload_url`, `upload_url_list`, `verify_url`
  и `voice_url` загружаются как аудиофайлы, а не вводятся вручную как URL.
- Основное поле формы привязывается к `prompt` либо `text` выбранной модели.
  Модели без текстового входа не требуют фиктивный промпт.
- Динамический тариф поддерживает `per request` и `per 1000 characters`;
  генерация остаётся заблокированной, если опубликованная цена отсутствует или
  её единица пока не поддерживается.

### Health-контракт при недоступной БД

`GET /api/health` возвращает HTTP 200 только при доступном подключении к БД
или когда продуктовая БД отключена штатно. При `database.state=unavailable`
ответ имеет HTTP 503 и `ok=false`, сохраняя диагностический объект `database`
без раскрытия внутренних ошибок. Поле `generationConfigured` безопасно
вычисляется и при отсутствии legacy media-service (например, в изолированном
HTTP-тесте).

### Загрузка защищённых скриптов при сбое БД (2026-09-18)

Статические JS/CSS проходят проверку сессии и существующие ограничения ролей,
но не вызывают accounts.scope и не инициализируют хранилище/очередь аккаунта.
При временной ошибке соединения повторяется только чтение сессии для известных
GET/HEAD ресурсов: до трёх попыток, задержки 150 и 300 мс. Отсутствие сессии,
запрет роли и нетранзитные ошибки не повторяются. POST/API операции не
повторяются этим механизмом. При исчерпании попыток сохраняется HTTP 503.

Повод: ошибка `window.attachFileDrop is not a function`; в журнале работающего
сервиса зафиксированы обрывы БД, а версии исходников в образе были актуальными.
Точный неуспешный браузерный запрос пользователя не записан. Механизм проверен
инъекцией ECONNRESET для file-drop.js в test/web-ui-smoke.cjs: скрипт повторно
загружается и файловое поле отображается. test/web-service.test.js проверяет
лимит повторов, отсутствие scope для статики и сохранение HTTP 401/403.

- Выбор модели передаётся по уникальному catalog id, а не неоднозначному API name.
- Request id + SHA-256 параметров дедуплицируют повторное добавление задачи;
  конфликт содержимого с тем же id отклоняется. Последовательная очередь записи
  не позволяет двум одновременным повторам создать две записи.
- Существующие правила TaskQueue о pause/recovery/unknown сохраняются.
  Очередь живёт на сервере; закрытая вкладка её не останавливает.
- HTTP отдаёт только разрешённые public/shared файлы и методный allowlist;
  исходники по hash, результаты по record id/index. Путь результатов проверяется
  внутри серверного каталога. Нет file:// ссылок и путей сервера в списке истории.
- JSON RPC до 4 MiB; исходники до настроенного лимита (64 MiB). Сервер запрещает
  cross-origin и неожиданный Host. Нет публичного login/auth для веба.
- Черновики shared UI сохраняются на сервере. Браузер имеет pending localStorage
  snapshot на случай ошибки; незавершённое чтение файла не гарантирует восстановление.
- Telegram: private allowlist, черновик на chat id, выбор модели/параметров/файлов,
  отдельное подтверждение. Его token становится durable request id; replay не
  повторяет платную задачу. Новое изменение черновика инвалидирует подтверждение.
- Offset Telegram сохраняется до отправки ответа. Потеря ответа не означает
  необходимость повторного платного действия; историю можно запросить отдельно.
- Завершение/ошибки бота проверяются после polling, уведомление сохраняет отметку.
  Нет exactly-once гарантии доставки уведомления при аварии между send и записью.
- При остановке закрываются polling, SSE, HTTP и очередь, затем снимается lock.
  После аварии stale lock требует проверки завершения процесса и ручного удаления.

## Переносимый модуль

Web/bot выделены в web-tg/ с собственными package.json, pnpm-lock.yaml, src, public, test, конфигом и данными. Внешние относительные импорты запрещены проверкой standalone.test.js. Копии каталога и компонентов прототипа развиваются самостоятельно. Desktop src/renderer.js, drafts.js и costs-ui.js возвращены к исходному desktop-поведению; Electron не зависит от web-tg. Корневые start:web/check:web/test:web делегируют модулю. Данные сервиса перенесены без изменения формата. Инструкции переноса: web-tg/README.md.

Проверка после выделения: 13 тестов web/bot (включая границы импортов), 45 desktop-тестов, check/check:web, pack и smoke собранного app.asar с --disable-gpu прошли. HTTP нового процесса из web-tg вернул health=true и 149 моделей. Ключи не настроены; внешние генерации и Telegram delivery не проверялись.

Добавлен generation-log: JSONL с ротацией, AsyncLocalStorage request/job/task correlation, запросами/ответами Kie и событиями Telegram без токена. Контракт — docs/generation-logging.md в модуле. Не отдавать логи публичным HTTP API.

Стоимость видна в текущем предпросмотре, очереди и истории desktop/web. Оценка отделена от факта, unknown не равен нулю. Web сохраняет оценку из кэша тарифов вместо пустой таблицы. Nano Banana Pro/2/2 Lite имеют автономный снимок публичных тарифов Kie от 2026-09-17 в tariff-snapshot.js; актуальные однозначные тарифы имеют приоритет. Проверки generation-cost.test.js.

Ошибки провайдера: errorInfo с category/providerCode/providerMessage/message/action/retryable/automaticRetry=false/taskId/stage. Исходные диагностические строки очищены от секретов. 400 не доказывает блокировку контента; 524 — timeout; неоднозначная отправка — submission_unknown без повтора. Явно отклонённые запросы становятся fail, транспортная неопределённость остаётся unknown. Копии provider-errors.js есть в desktop и переносимом web-tg. Старые записи отображаются через классификацию на чтении без миграции истории.

Новые вкладки desktop/web и новые Telegram-сессии по умолчанию используют Nano Banana 2 Lite (startupDefault в каталоге). Промпт идёт первым; image_urls необязателен, без исходника — text-to-image. Старые черновики/сессии не перезаписываются. UI smoke проверяет модель старта и необязательное поле.

Текущий доступ Telegram: все личные чаты принимаются независимо от TELEGRAM_ALLOWED_USER_IDS; список задаёт операторов. Обычные пользователи видят и отменяют только свои задачи; уведомления отправляются владельцу результата без фильтра операторов. Для запуска нужны enabled и token. Обычная внешняя навигация GET/HEAD / и /index.html разрешена; Host и защита API сохранены. Проверено 19 тестами.

Уточнение доступа: TELEGRAM_PUBLIC_ACCESS=true (по умолчанию) открывает личные чаты всем; false включает TELEGRAM_ALLOWED_USER_IDS для команд, callback и уведомлений. Пустой список в закрытом режиме запрещает всем. Список продолжает определять операторов в обоих режимах; данные сохраняются при переключении. Отдельная регистрация через Telegram отложена.

## Telegram account linking — 2026-09-23

Добавлена привязка Telegram из авторизованного аккаунтного меню через одноразовый
deep link `/start <token>` (10 минут, в БД сохраняется только SHA-256). Связь
уникальна с обеих сторон; Telegram ID проверяется как `from.id` входящего личного
сообщения. После привязки черновик, история и очередь бота берутся из связанного
account-scoped сервиса. Создание задачи проходит защищённый account dispatch,
серверный тариф, резерв и баланс; callback использует account-bound request ID
для дедупликации. Notifications используют сохранённый Telegram ID. Отвязка
останавливает новые команды, текущая история/задачи остаются в сайте. Отдельная
Telegram-регистрация не добавлена. Стартовый GPT-only пакет не получает Kie-доступ
из бота. Проверка интеграции выполняется на свежем Compose runtime через health,
а полное подтверждение требует открыть одноразовую ссылку и отправить `/start`
через Telegram.
